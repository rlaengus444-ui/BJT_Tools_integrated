# BJT Shell/격자 메모리 최적화 계획

기준 upstream 커밋은 `8a8f057c6d192de082a6a14f12397e1303653ee0`이다. 로컬 `e16f48fff76b43b68a43d19ea237031d953c2405`는 소스 스냅샷 전달용 기준이다. 요청된 역할은 설계 `gpt-6.1-sol/max`, 단순 구현 `gpt-6.1-terra/medium`, 복잡한 구현과 독립 검토 `gpt-6.1-sol/max`이며 네이티브 협업 경로를 사용한다. 구현 후 독립 검토가 완료되었으며 차단 또는 미해결 코드 지적은 없다. 상세 근거는 [REVIEW.md](REVIEW.md)에 기록한다.

## 1차 범위와 불변 조건

- STL 통계는 정점 필드별 finite 검사와 bounds 축약을 사용한다. 차분과 외적은 float64로 계산하고 퇴화 판정 `<= 1e-24`를 유지한다.
- STL writer는 전체 배치의 float32 복사 없이 청크별로 변환하고 양의 정수 `chunk_size`를 정규화한다.
- edge 검사는 32바이트 레코드의 앞 세 word를 복사 없는 `<u8` view로 사용하고 이전 청크 임시 배열을 해제한다. 단일 청크에서는 concatenate를 생략한다.
- 출력 바이트와 순서, winding, 접촉 분류, 해시, 파일 형식, 취소 동작 및 기존 제한을 유지한다.

제거 대상 임시 메모리의 이론적 크기는 writer에서 `36 × N` 바이트, edge key에서 `24 × edge_count` 바이트다. 이는 전체 애플리케이션 RAM 절감량이나 최고 사용량을 보장하지 않는다.

현재 v5.7의 rectangle meshing, Numba, 공유 endpoints, 외부 endpoint 정렬은 이미 최적화되어 있다. 이번에는 Rust 전면 재작성이나 형상·bucket sort 구조 변경을 하지 않는다. 변경 후 프로파일링이 뒷받침하는 경우에만 정확한 edge 정렬/계수와 rectangle에서 레코드로 직접 출력하는 커널을 향후 Rust 후보로 검토한다. 선택적 백엔드의 패키징과 fallback도 함께 평가한다.

## 검증 계획과 한계

실제 운영 함수 정의를 AST로 추출하여 앱 부트스트랩 없이 검사하고 오프라인 edge 정확성 시험에서는 Numba decorator만 제거한다. 이 시험은 JIT 실행을 검증하지 않는다. writer는 임베디드 `BinarySTLWriter`의 실제 생성부터 종료까지 검사한다. 통계 및 출력 시험은 비정상·잘린 파일, nonfinite 값, 빈 입력, 여러 청크, 취소, 경계 및 해시를 포함한다.

별도 프로세스의 합성 벤치마크에서 원본과 변경본을 번갈아 반복 실행하여 시간과 native peak RSS를 측정한다. 시간 값은 테스트의 합격 조건으로 고정하지 않는다. 사용자는 임시 가상환경 의존성 설치를 승인했으며 설치가 완료되었다. Python 경로 23개 시험(0.64초)과 native 경로 23개 시험(2.65초)을 실행했다. 소스 출처를 고정한 최종 전체 파이프라인 비교의 6개 사례가 차이 없이 통과했고 11개 manifest 항목의 해시와 크기가 일치했다. 비교 범위는 이미지 픽셀 해시, STL 통계와 파일 해시, preview callback 횟수, 최종 progress 100 및 report status다. 구현 후 독립 검토가 완료되었으며 차단 또는 미해결 코드 지적은 없다. GUI와 Windows EXE는 아직 실행하지 않았다. 빌드, 릴리스, 업로드 및 push는 수행하지 않는다.
