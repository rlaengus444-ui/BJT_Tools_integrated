# 사전 설계 검토 · 모델 자동 배치 통합

- 기준: v1.8.0, `b162078a377300636f4ec0d15e7287599d4efb27`.
- 실제 호출: native `collaboration.spawn_agent`, `/root/sol_reviewer`.
- 요청 모델·추론: `gpt-6.1-sol` / `max`.
- 완료: 구현 전 최종 검토 응답을 받았으며, Tk 통합 설계를 조건부 타당으로 평가했다. 이 기록은 구현 후 diff 검토를 대신하지 않는다. 제공 모델의 신원을 별도로 검증했다고 주장하지 않는다.

반영할 조건:

1. 기존 1.8 Rust 개선과 11개 도구를 보존하고 12번째 배치 도구를 등록한다.
2. Qt 별도 창 대신 Tk/ttk와 `FigureCanvasTkAgg`로 기존 테마·설정·중단 수명주기에 연결한다. 배포 VTK의 Tk 네이티브 모듈 부재를 고려한다.
3. 표시용 메시만 전역 삼각형 예산으로 줄이고 원본·검증·내보내기 형상은 그대로 사용한다. `matrices_for`로 원래 좌표 원점까지 적용한다.
4. 배치 엔진은 기존 검증 소스를 그대로 포함하며 GUI·명령줄·학습 실행 모듈을 제외한다. 제공 정책은 추론에만 사용한다.
5. 원래 NumPy/SciPy/Trimesh 등의 버전은 유지하고 VTK 9.3.1과 맞는 OCP 7.8.1.1.post1을 추가한다. 실제 호환성 검사를 실행한다.
6. Tk 접근은 주 스레드, 계산은 단일 추적 worker와 cancel_event를 사용한다. 작업/입력 revision으로 오래된 이벤트를 거부한다. optimize 전체에 cancellation_scope를 씌우지 않는다. 최종 검증·저장 정리 완료까지 기다린다.
7. 결과는 해당 모델·수량·조건의 스냅샷으로 소유하고 입력 변경 시 무효화한다. 기존 STL/CHITUBOX 내보내기를 그대로 호출한다.
8. schema 1에 새 도구 namespace만 추가한다. 경로·단위·수량·허용 자세·프로필만 보존하고 복원 시 CAD 파일을 자동으로 읽지 않는다.
9. 모든 배포 엔진 파일의 해시·라이선스·네이티브 라이브러리·PyInstaller 수집 및 12개 도구 검증을 갱신한다. 1.8 네이티브 배포 게이트는 유지한다.
10. 요청된 단독 `.py`는 통합 런타임 밖에 별도 보관하고 소스 ZIP에 포함한다. Windows EXE 검증은 실제 Windows 실행 근거 없이 완료로 표시하지 않는다.

검토자는 소스 해시 27/27, 11개 도구 등록, 원본 정책 JSON 해시와 학습 608회·갱신 12,825회·범위 157개를 읽기 전용으로 확인했다. 당시 GUI 실행·EXE 빌드·업로드·기존 386개 테스트 재실행은 수행하지 않았다.
