# STEP 다중 솔리드 가져오기 수정 · 1.9.2

첨부된 M8 나사 STEP은 유효한 CAD 솔리드 6개를 포함하지만 작은 나사산 바디가 본체와 겹친다. 1.9.1은 각 바디의 표면을 연결해 계산용 메시를 만들기 때문에 내부 겹침을 실제 자기 교차로 판정했다. 기존 오류의 삼각형 쌍은 1137/5377이다. 파일명이나 `.STEP.step` 확장자가 원인은 아니다.

1.9.2는 STEP의 CAD 복사본에서 재료 영역의 합집합을 계산한 후 삼각화한다. OCCT 기본 공차를 늘리지 않고, 단순화나 메시 검사 생략을 하지 않는다. 단일 솔리드, 분리된 재료 및 내부 빈 공간을 보존한다. 원본 BRep과 디스크 입력은 그대로 두고, STL의 엄격한 교차·닫힘·다양체 검사도 유지한다. 합집합 실패·유효하지 않은 결과·솔리드 밖의 열린 형상은 거부한다. 작업 결과의 면·변·정점 공차를 모두 삼각화 오차 여유에 포함한다.

## 첨부 모델 검증

원본 CAD와 생성 메시를 저장소/배포본에 넣지 않았다. `private-model-verification.json`은 파일 해시와 검사 수치만 기록한다.

- 원본 SHA-256: `7fc413b310f6220002f3d0a7798ba799525584412f0be0d0d950e0b7bc854ef1`
- 입력 6개 솔리드 → 계산용 재료 1개, 2,556 정점·5,108 삼각형
- 크기 8 × 8 × 25 mm, 메시 부피 1,373.1564989154313 mm³
- CAD 합집합 부피 1,373.3511498871007 mm³, 선언된 삼각화 여유 0.02020294226589598 mm
- 통합 서비스의 가져오기·2개 배치·독립 최종 검사·STL/CHITUBOX 저장·저장 파일 재읽기 통과
- 원본 파일 SHA-256 보존, 원본 BRep 직렬화 및 삼각화 상태 보존 검사 통과

위 CAD/메시 부피 차이는 기본 0.02 mm 곡면 삼각화에 따른 근사이다. 기존과 같이 엄밀한 Hausdorff 오차 보증으로 표현하지 않는다.

재현:

```bash
.venv/bin/python release_tools/verify_step_material_import.py \
  --input '개인 STEP 경로' --output /별도/검증출력
```

## 검사 및 독립 검토

다중 바디의 겹침·완전 포함·중복·면 접촉·분리, 공동과 내부 삽입체, 점/선 접촉 거부, 열린 형상 거부, 잘못된 STL 거부, Boolean 실패, 뒤집힌 무한 솔리드 거부, 디스크 캐시와 검사 코드 변경에 따른 캐시 무효화를 검사한다. 소스의 집중 검사는 42개 및 하위 검사 3개 통과, Linux 표시 환경이 없어 GUI 검사 15개는 건너뛰었다. 로컬 전체 검사 수집은 관련 없는 기존 의존성 `manifold3d` 부재로 완료하지 못했다. Windows의 고정 의존성 환경에서 전체 검사를 별도로 수행한다.

저장소 지침에 따라 네이티브 협업 도구로 `gpt-6.1-sol` / `max`를 요청한 `m8_step_review`를 실제 호출해 설계 및 구현을 검토했다. 검토에서 발견한 숫자 PE 버전 불일치, 소스 실행기 템플릿 회귀, NaN 검사 누락 및 뒤집힌 솔리드의 재료 해석 오류를 수정하고 독립 재검토를 완료했다. 남은 코드 검토 지적 사항은 없다. 실제 요청 경로·설정·검토 대상 파일 해시·실행 검사는 `sol-review.json`에 기록했다. Windows 배포 결과는 후속 증거에 기록한다.

실제 프린터/장비 또는 CHITUBOX 앱 실행 검증을 의미하지 않는다.
