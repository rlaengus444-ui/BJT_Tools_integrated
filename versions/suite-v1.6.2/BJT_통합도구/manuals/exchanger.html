1. 제품 개요와 교체 원리

이 도구는 A 폴더의 지정 번호 구간을 B 폴더의 지정 번호 구간으로 교체합니다. A는 실제로 내용이 바뀌는 대상이며 B는 읽어서 복사하는 소스입니다. A의 파일명·번호 체계는 유지하고 B의 이미지 파일 내용을 순서대로 A 파일에 덮어씁니다. 별도 결과 폴더를 만드는 도구가 아니므로 실행 전에 A/B 역할과 범위를 정확히 확인합니다.

  1. A 폴더와 B 폴더, 양쪽 시작·끝 번호를 지정합니다.
  2. 지정 범위 누락과 각 대응 파일의 이미지 형식을 검사합니다.
  3. A의 교체 대상 파일을 A 내부의 자동 백업 폴더에 복사합니다.
  4. B 파일을 대응하는 A 파일에 덮어씁니다.
  5. 교체 결과인 A 폴더 전체 숫자 이미지의 번호 누락과 해상도·원본 비트 수·실제 파일 형식의 일관성을 자동 검사합니다. 교체 또는 최종 검사에서 실패하면 백업으로 복원을 시도합니다.
확인 사항

번호 범위는 양끝을 포함합니다. A 61~120과 B 1~60은 각각 60개이며 A 61←B 1, A 62←B 2, …, A 120←B 60으로 대응합니다. 내용 교체 후에도 A 파일명은 61.png~120.png로 유지됩니다.

2. 빠른 시작과 실행 전 확인

  1. A가 교체 대상, B가 사용할 이미지 원본인지 탐색기에서 확인합니다. 같은 폴더를 양쪽에 지정하지 말고 서로 다른 준비 폴더를 사용합니다.
  2. [A 폴더 / 교체될 폴더]의 [찾기]로 A를 선택합니다. [B 폴더 / 소스 폴더]의 [찾기]로 B를 선택합니다.
  3. 각각 A 시작 번호·A 끝 번호·B 시작 번호·B 끝 번호를 입력합니다. 숫자 파일명에서 확장자와 앞자리 0을 제외한 정수 번호를 사용합니다.
  4. A 개수=A 끝−A 시작+1, B 개수=B 끝−B 시작+1을 계산하여 같음을 확인합니다.
  5. A 전체에 원래부터 빠진 숫자나 형식이 다른 이미지가 없는지 확인합니다. 최종 검사는 교체 구간뿐 아니라 A 전체를 검사합니다.
  6. [검사 후 교체 실행]을 누릅니다. 실제 덮어쓰기·자동 백업·실패 시 복원 시도 안내를 읽고 확인 대화상자에서 진행을 선택합니다.
  7. 로그의 [1/6]~[6/6]을 확인하고 최종 검사의 대상 파일 수·해상도·비트 수·실제 형식과 작업 성공 메시지를 확인합니다. 완료 알림은 A 전체 자동 검사까지 통과한 뒤 표시됩니다. 완료 후 경계 구간과 백업 폴더를 확인합니다.

미리보기 화면은 제공하지 않습니다. 실행 전에 파일의 내용을 확인하려면 탐색기나 이미지 뷰어를 사용합니다. [로그 지우기]는 화면의 로그만 지우며 파일·백업·작업 상태를 바꾸지 않습니다. 작업 중에도 로그를 지우면 앞선 검사 기록을 화면에서 볼 수 없으므로 완료 후 정리할 때 사용합니다.

3. 지원 형식과 번호 인식

항목규칙·예시
지원 확장자.png, .bmp, .tif, .tiff, .jpg, .jpeg. 확장자 대소문자는 인식 시 소문자로 취급합니다.
지원 파일명확장자를 제외한 이름이 숫자만인 파일. 1.png, 0001.png, 120.tif 등.
번호 해석0001.png와 1.png는 모두 번호 1입니다. A/B 간 앞자리 0의 개수는 달라도 번호로 대응합니다.
수집 범위선택 폴더 바로 아래의 파일만 수집합니다. 하위 폴더와 자동 백업 폴더는 탐색하지 않습니다.
제외되는 이름layer1.png, 1_copy.png 같은 이름과 지원하지 않는 확장자는 번호 이미지 목록에 포함되지 않습니다.
중복 번호같은 폴더의 1.png와 001.png 또는 1.png와 1.bmp는 중복 번호로 오류 처리합니다. 선택 범위 밖의 중복도 목록 수집 단계에서 발견됩니다.
정렬·대응문자열 순서가 아니라 입력한 정수 번호에 따라 대응합니다. A의 n번째 지정 번호에 B의 n번째 지정 번호가 연결됩니다.

폴더 경로 입력칸은 경로 직접 입력·찾기·폴더 드래그앤드롭을 지원합니다. 드롭은 각 입력칸에 폴더 하나씩 수행합니다. 파일 드롭은 허용하지 않으며 여러 경로를 한 번에 떨어뜨려 일괄 등록하는 용도가 아닙니다. 드래그앤드롭 기능을 사용할 수 없으면 [찾기]를 사용합니다.

참고

A/B의 대응 파일은 같은 확장자·실제 이미지 형식·가로세로 픽셀 크기·모드·채널 구성·원본 비트 수여야 합니다. PNG와 JPEG가 눈으로 같거나 RGB8과 RGB16이 같은 RGB로 표시되어도 서로 다른 조건입니다. PNG·TIFF·JPEG는 원본 정밀도로 해독하고 TIFF는 전체 프레임을 확인합니다. BMP는 기존 Pillow 기반 모드·밴드·비트 정보 검사를 유지합니다.

4. 화면 항목과 입력 조건

화면 항목초기값·단위조건과 역할
A 폴더 / 교체될 폴더비어 있음 / 폴더 경로실제로 파일 내용이 바뀌는 대상. 기존 폴더여야 합니다.
B 폴더 / 소스 폴더비어 있음 / 폴더 경로A에 넣을 이미지를 제공하는 기존 폴더.
A 시작 번호비어 있음 / 파일 번호A에서 첫 번째로 교체할 번호. 정수.
A 끝 번호비어 있음 / 파일 번호A에서 마지막으로 교체할 번호. 시작 이상.
B 시작 번호비어 있음 / 파일 번호B에서 첫 번째로 읽을 번호. 정수.
B 끝 번호비어 있음 / 파일 번호B에서 마지막으로 읽을 번호. 시작 이상이며 A와 개수가 같아야 함.
검사 후 교체 실행실행 가능입력 확인과 사용자 확인 뒤 백그라운드로 검사·백업·교체·A 전체 자동 검사. 실행 중 비활성화.
로그 지우기실행 가능화면 기록만 삭제. 작업 취소 기능이 아닙니다.

이 탭에는 DPI, 캔버스 크기, 임계값, 색상 변환, 이미지 보간 설정이 없습니다. 교체 중 이미지의 크기나 픽셀을 다시 계산하지 않고 원본 파일을 복사합니다. 번호 필드에는 61처럼 정수를 입력하며 61.png 또는 61~120처럼 확장자·범위를 넣지 않습니다. 음수 파일명은 숫자 파일로 인식되지 않으므로 실제 존재하는 비음수 번호를 사용합니다.

확인 사항

이 탭의 A/B 경로와 범위가 다음 실행에도 자동 저장된다고 가정하지 마십시오. 작업을 시작할 때 매번 화면의 여섯 입력값을 확인합니다. 전용 실행 단축키는 없으며 버튼으로 실행합니다.

참고

교체 후 검사는 항상 [6/6] 단계에서 자동 실행됩니다. 별도의 결과 폴더나 후검사 버튼을 지정할 필요가 없으며, 검사할 결과 폴더는 내용이 교체된 A입니다. DPI는 이 검사의 일치 조건에 포함하지 않습니다.

5. 검사 단계와 합격 기준

단계검사·작업확인할 내용
1/6숫자 이미지 파일 목록 수집폴더별 이미지 수와 중복 번호 오류.
2/6지정 범위 누락 파일 검사A/B 모두 지정한 모든 번호가 존재해야 합니다. 누락 번호를 로그에 표시합니다.
3/6대응 파일의 원본 정밀도와 실제 형식 검사A 시작+i와 B 시작+i의 확장자·실제 형식·해상도·원본 비트 수·채널과 프레임 구성이 같아야 합니다.
4/6A 폴더 원본 백업교체 대상만 백업합니다. 폴더 경로가 로그에 표시됩니다.
5/6B 이미지 내용으로 A 파일 덮어쓰기대응 B 파일을 기존 A 경로에 복사합니다.
6/6A 전체 자동 최종 검사A 바로 아래의 전체 숫자 이미지에 대해 최솟값~최댓값 사이 번호 누락이 없고, 해상도·원본 비트 수·실제 형식 등 검사 속성이 기준 파일과 같아야 합니다. 교체 구간 밖도 검사합니다.

최종 형식 검사는 A에서 가장 작은 번호의 파일을 기준으로 합니다. 전체 숫자 이미지의 확장자, 실제 파일 형식, 가로세로 픽셀 크기, 모드·채널 구성, 채널당 원본 비트 수와 픽셀당 비트 수 등 검사 속성을 비교합니다. PNG·TIFF·JPEG는 원본 정밀도로 전체 픽셀을 해독해 정보를 확인하며, 16비트를 8비트로 낮추어 같은 형식이라고 판단하지 않습니다. TIFF는 첫 페이지만 보지 않고 전체 프레임의 해상도·비트 수·채널 구성도 확인합니다. BMP는 기존 Pillow 기반 검사를 사용합니다.

참고

검사 범위는 A 폴더 바로 아래에서 지원 확장자이고 이름이 숫자만인 이미지 전체입니다. preview.png, layer1.png, 1_copy.png 같은 비숫자 이름과 하위 폴더·백업 폴더는 제외합니다. DPI 메타데이터는 일치 조건으로 비교하지 않습니다. 각 레이어의 이미지 내용은 원래 다를 수 있으므로 서로 같은 픽셀 그림인지 요구하는 검사도 아닙니다.

확인 사항

A 번호가 반드시 1부터 시작할 필요는 없습니다. 61~180만 있고 그 안이 연속이면 번호 조건은 통과합니다. 현재 존재하는 최솟값~최댓값을 사용하므로 작업의 실제 처음·마지막 층이 원래부터 통째로 빠져 있는지는 이 조건만으로 알 수 없습니다. 실제 총 층 수와 선택 폴더는 별도로 확인하세요.

해상도나 비트 수가 다른 이미지가 교체 범위 밖에 있어도 [6/6]에서 실패합니다. 이 경우 이번에 교체한 범위를 백업으로 자동 복원하지만, 원래부터 있던 범위 밖의 문제 파일이나 누락을 새로 고치지는 않습니다. 형상의 배치·내용이 의도한 설계인지 판단하려면 원본 이미지와 별도의 일치성·위치 검사를 함께 사용합니다.

6. 작업 예제 ① A의 61~120층을 B의 1~60층으로 교체

예제 조건: A에는 1.png~180.png, B에는 1.png~60.png가 있으며 모두 2000×2000 px의 L 모드 PNG입니다. A의 전체 번호가 연속이고 이미지 형식도 같습니다. 목표는 A의 61~120층만 수정된 B 이미지로 바꾸는 것입니다.

입력예제값
A 폴더D:/Job/Original_A
B 폴더D:/Job/Revised_B
A 시작 / 끝61 / 120
B 시작 / 끝1 / 60
개수A:120−61+1=60, B:60−1+1=60
  1. A/B 경로와 위 네 번호를 입력합니다. A 60.png와 121.png는 교체하지 않는 경계 파일임을 확인합니다.
  2. [검사 후 교체 실행]을 눌러 확인 대화상자에서 진행합니다.
  3. [4/6] 로그에 표시된 _backup_before_replace_날짜_시간 경로를 확인합니다.
  4. [6/6]에서 전체 180개 숫자 이미지의 누락·해상도·비트 수·실제 형식 검사가 끝날 때까지 기다립니다. 성공 집계에 표시된 파일 수와 기준 형식이 의도한 값인지 확인합니다.
  5. 작업 성공 후 A 61.png를 B 1.png와, A 120.png를 B 60.png와 대조합니다. A 파일명은 그대로이며 A의 전체 파일 수는 180개입니다.
  6. 백업 폴더의 61.png~120.png는 교체 전 A의 원본입니다. 필요할 때 사용할 수 있도록 보존합니다.

Revised_B/1.png … 60.png

…

7. 작업 예제 ② 서로 다른 번호 구간과 실패 시 복원

예제 조건: A 121~150층에 B 501~530층을 넣으려 합니다. 두 구간은 각각 30개입니다. 번호 자체가 같을 필요는 없으며 A 121←B 501, …, A 150←B 530으로 연결합니다. B가 0501.png처럼 0으로 시작해도 번호 501로 인식합니다.

  1. A 시작=121, A 끝=150, B 시작=501, B 끝=530을 입력합니다.
  2. B 510.png의 크기가 A 130.png와 다르면 [3/6]에서 형식 불일치로 실패합니다. 이 단계는 백업·덮어쓰기 전에 수행되므로 A는 교체되지 않습니다. 크기·모드를 수정한 후 다시 실행합니다.
  3. 대응 형식은 맞지만 A 전체에서 180.png가 빠져 있고 181.png 이후 파일이 존재한다면 [6/6] 전체 연속성 검사에서 180 누락을 발견합니다.
  4. 이 경우 A 121~150을 저장된 백업으로 자동 복원하고 로그에 [자동복구 완료]를 남깁니다. B는 변경하지 않습니다.
  5. 원래 A에 있던 180 누락은 자동 복원으로 해결되지 않습니다. 원래 데이터의 누락을 정리하고 A 전체 조건이 맞는 상태에서 다시 실행합니다.
일시 교체: A/121.png ← B/501.png … A/150.png ← B/530.png
최종 검사: A/180.png 누락 발견
자동 복원: 백업/121.png → A/121.png … 백업/150.png → A/150.png
보존 결과: A의 교체 대상은 작업 전 내용, 백업 폴더 유지
주의: 원래부터 없던 A/180.png는 복원으로 새로 생성되지 않음
확인 사항

실패했다고 해서 항상 모든 파일 복원이 성공했다고 가정하지 않습니다. [자동복구 실패 항목] 또는 일부 복구 실패 메시지가 있으면 로그의 파일명과 보존된 백업 폴더를 확인하고 해당 파일을 직접 복원해야 합니다.

추가 확인 사례검출 시점결과
A의 교체 구간 밖 160.png만 다른 해상도대응 교체 구간은 정상이어도 [6/6] A 전체 검사에서 불일치이번 교체 범위는 백업으로 복원. 원래부터 다른 160.png는 별도 정리
대응 파일이 PNG RGB16과 RGB8둘 다 RGB처럼 보여도 [3/6]에서 원본 채널당 16비트와 8비트 차이 검출백업·덮어쓰기 전에 실패. A는 교체되지 않음
TIFF 첫 페이지는 같지만 뒤 페이지의 크기·비트 수가 다름대응 파일이면 [3/6], A의 다른 파일이면 [6/6]에서 전체 프레임 검사발견 단계에 따라 교체 전 실패 또는 이번 교체 범위 자동 복원

8. 백업 관리와 수동 복원

백업 폴더 이름은 _backup_before_replace_YYYYMMDD_HHMMSS이며 A 안에 생성됩니다. 백업은 A 전체의 사본이 아니라 이번 지정 구간의 파일 사본입니다. 성공 후에도 자동 삭제하지 않으며, 실패 후 자동 복구에 사용한 백업도 보존합니다. 로그의 실제 경로로 해당 작업의 백업을 구분하십시오.

  1. 수동으로 되돌릴 경우 먼저 이 탭의 작업이 완료·실패하여 더 이상 파일을 쓰지 않는 상태인지 확인합니다.
  2. 로그의 백업 경로를 열고 원래 A 파일명과 대상 범위를 확인합니다. 여러 번 실행했다면 되돌리려는 시점의 백업을 고릅니다.
  3. 해당 백업의 대상 파일을 A의 같은 파일명으로 복사하여 덮어씁니다. 예를 들어 61~120 백업이면 그 60개 파일만 A에 돌려놓습니다.
  4. 복사 후 파일 개수·크기·내용을 점검합니다. 프로그램에 별도 [백업 복원] 버튼은 없습니다.
확인 사항

A/B/백업을 다른 프로그램에서 동시에 편집·이동·삭제하지 마십시오. 자동 복구는 보존된 백업을 다시 복사하는 방식이며, 쓰기 권한·저장 장치·파일 잠금 문제 때문에 일부 복구가 실패할 수 있습니다. 백업은 복구가 완료되고 필요한 결과가 확인되기 전까지 보존하십시오.

파일 복사를 사용하므로 B의 이미지 인코딩·픽셀·파일 메타데이터를 가져오며 A의 경로 이름은 유지합니다. 별도 재압축·리사이즈·DPI 재설정·회전은 수행하지 않습니다. B 소스 파일 자체를 이름 변경하거나 삭제하지 않습니다.

9. 진행 상태·종료·로그 확인

진행률 막대 대신 로그에서 현재 단계를 확인합니다. 대응 형식 검사·백업·교체뿐 아니라 최종 A 전체 형식 검사도 100개마다 또는 해당 단계 마지막에 처리 개수를 기록합니다. 최종 검사 로그의 대상 파일 수와 기준 해상도·원본 비트 수·실제 파일 형식을 확인합니다. 큰 이미지나 다중 페이지 TIFF에서는 로그가 잠시 늘지 않아도 한 파일을 원본 정밀도로 해독하고 있을 수 있습니다.

  • 실행 중 [검사 후 교체 실행]은 비활성화되어 같은 탭에서 다시 실행하지 못합니다.
  • 이 도구는 교체 중 임의 중단을 제공하지 않습니다. 통합 프로그램 상단 [현재 작업 중단]도 범위 교체 탭에서는 비활성화됩니다.
  • 프로그램을 닫을 때 진행 중이면 통합 프로그램의 종료 안내를 확인하고 작업·복원 정리가 끝날 때까지 기다립니다.
  • 완료 알림은 최종 전체 검사까지 통과한 경우에 표시됩니다. 실패 알림이면 로그 아래의 오류 상세와 자동복구 상태를 함께 확인합니다.
  • [로그 지우기]는 작업 중단이나 복원을 실행하지 않습니다. 중요한 경로·오류 기록은 지우기 전에 복사해 두십시오.
참고

강제 종료로 파일 복사를 끊으면 자동 복원 절차가 끝나지 않을 수 있습니다. 정상적인 완료·실패 알림을 기다리고, 다음 작업 전에 A와 백업의 실제 상태를 확인하십시오. 이 탭은 취소 후 이어하기 기능을 제공하지 않습니다.

자동 최종 검사는 해상도·원본 비트 수·실제 형식 확인을 위해 전체 이미지를 해독하므로, 파일 이름만 읽는 번호 검사나 동일 파일 해시로 해독을 생략하는 빠른 비교보다 오래 걸릴 수 있습니다. 처리 메모리는 원본 해상도·채널 수·비트 수의 영향을 받습니다. 별도의 빠른 검사·정밀 검사 선택칸은 이 탭에 없습니다.

10. 문제 해결과 용어

증상·메시지확인 및 조치
번호는 숫자로 입력해야 함시작·끝 칸에 확장자·공백 구간 표시 없이 정수를 입력합니다.
A/B 범위 개수가 다름끝−시작+1로 양끝 포함 개수를 다시 계산합니다.
지정 범위 숫자 파일 누락로그의 번호가 실제 숫자 이름 파일로 존재하는지, 지원 확장자인지 확인합니다.
같은 숫자 이름 중복1.png와 001.png 또는 확장자가 다른 같은 번호 파일을 정리합니다. 지정 범위 밖도 확인합니다.
대응 파일 이미지 형식이 다름확장자·실제 형식·픽셀 크기·모드·채널·원본 비트 수·전체 프레임 구성 중 다른 항목을 로그에서 비교합니다.
A 전체 숫자 파일에 빠진 번호A의 최소~최대 번호 사이 누락을 확인합니다. 교체 구간 밖의 원래 누락도 실패 원인입니다.
A 전체 이미지 형식이 일관되지 않음최소 번호 기준 파일과 문제 파일의 해상도·원본 비트 수·실제 형식·프레임 정보를 비교합니다. 이번 교체 대상 외의 파일도 포함합니다.
복구 실패·접근 거부A와 백업의 쓰기 권한, 파일 잠금, 저장 공간을 확인하고 로그에 지정된 백업에서 복원합니다.
백업 폴더 생성 실패A 경로의 쓰기 권한을 확인합니다. 동일 초에 생성된 같은 이름 백업이 이미 있는 경우 잠시 후 다시 실행합니다.
RGB로 같아 보이는데 비트 수 불일치RGB8과 RGB16은 채널당 비트 수와 픽셀당 비트 수가 다릅니다. 원본 내보내기 설정을 확인합니다.
TIFF 첫 화면은 같지만 최종 검사 실패첫 페이지 이외 프레임의 해상도·비트 수·채널 구성이 다르거나 해독 오류가 있는지 로그에서 확인합니다.
미리보기 파일이 전체 검사에 포함되지 않음preview.png처럼 이름이 숫자만이 아니면 검사 대상이 아닙니다. 이 탭의 숫자 레이어 검사 범위를 확인합니다.
최종 검사에서 오래 걸림전체 이미지의 원본 정밀도 해독 중일 수 있습니다. 마지막 처리 개수와 파일 수를 확인하고 정상 완료·복원 정리를 기다립니다.
  • A(대상): 지정 번호 파일의 내용이 실제로 교체되는 폴더입니다.
  • B(소스): 복사할 이미지 내용을 제공하는 폴더입니다.
  • 대응 파일: A 시작+i와 B 시작+i로 연결된 한 쌍입니다.
  • 연속성: 최소 번호부터 최대 번호까지 빠진 정수가 없는 상태입니다.
  • 모드·밴드: L, RGB, RGBA 같은 픽셀 표현 방식과 채널 구성입니다.
  • 자동 복원: 교체·최종 검사 실패 시 백업 파일을 A의 원래 경로로 다시 복사하는 절차입니다.
  • 원본 비트 수: PNG·TIFF·JPEG의 저장 정밀도를 보존해 읽은 채널당 비트 수. RGB라는 모드 이름만으로 8비트와 16비트를 같다고 판단하지 않습니다.
