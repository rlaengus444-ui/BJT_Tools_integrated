1. 제품 개요와 검사 범위

슬라이싱 일치성 검사는 기준 묶음 A와 비교 묶음 B의 파일을 짝지어, 같은 좌표의 이미지 픽셀과 해상도·비트 수·실제 파일 형식·전체 파일 바이트가 같은지 확인합니다. 치환 전후의 복사 확인, 폴더와 ZIP의 내용 대조, 내보내기 결과의 차이 확인에 사용합니다. 모든 처리는 PC 안에서 이루어지며 입력 파일을 수정하지 않습니다.

확인하려는 내용이 탭에서 확인할 결과해석 범위
같은 파일이 모두 복사되었는가파일명 대응, A/B에만 있는 항목, 바이트 일치선택한 두 묶음에 실제로 들어 있는 파일 기준
그림의 위치·명도·형식이 같은가픽셀 일치, 해상도·비트 수·채널·형식 차이허용 오차 없이 원본 좌표와 원본 샘플로 비교
파일 자체가 정상적으로 해독되는가정밀 옵션과 검사 오류빠른 검사와 전체 픽셀 무결성 검사의 차이는 5장 참조
인접한 층에서 이동 신호가 생겼는가통합 프로그램의 ‘슬라이싱 위치 검사’ 탭 검토이 탭은 두 묶음의 대응 파일을 비교하며 이동량 dx/dy를 산출하지 않음
확인 사항

‘일치’는 선택한 항목과 검사 범위에 관한 결과입니다. 두 묶음에서 같은 층이 함께 빠져 있으면 서로 일치할 수 있습니다. 실제 작업의 총 층 수와 선택 범위도 별도로 확인하세요.

2. 빠른 시작 — 폴더와 ZIP 비교

  1. 통합 프로그램에서 ‘슬라이싱 일치성 검사’ 탭을 엽니다. 탭 상단 ‘사용설명서’ 또는 메인 창의 F1로 이 설명서를 다시 열 수 있습니다.
  2. A ‘기준 파일 묶음’ 영역에 기준 폴더를 놓습니다. ‘폴더 선택’ 버튼으로 지정해도 됩니다.
  3. B ‘비교 파일 묶음’ 영역에 비교 ZIP을 놓습니다. 이미지 여러 개를 선택하려면 ‘파일 / ZIP 선택’을 사용합니다.
  4. 파일명과 하위 경로가 같다면 ‘짝짓기 기준’을 기본값 ‘상대 경로 / 파일명’으로 둡니다.
  5. 기본 빠른 검사로 대조하려면 정밀 체크를 끈 상태로 ‘일치성 검사’를 누릅니다. 파일 자체의 전체 해독 검증도 필요하면 ‘정밀: 같은 파일도 전체 픽셀 해독’을 켠 후 실행합니다.
  6. 완료 문구와 항목 수를 확인합니다. 먼저 ‘차이 / 누락’과 ‘오류 / 미지원’ 필터를 보고, 행을 선택해 ‘검사 상세’의 근거를 읽습니다.
  7. 필요한 행에서 ‘이미지 미리보기’를 열어 표시를 확인합니다. 보관할 결과는 ‘JSON 저장’과 ‘CSV 저장’으로 원하는 위치에 저장합니다.
참고

새로 드롭하거나 선택하면 해당 영역의 기존 선택이 교체됩니다. A/B 입력, 짝짓기 기준 또는 정밀 옵션을 바꾸면 이전 결과와 저장 버튼이 초기화되므로 다시 검사해야 합니다.

3. 입력 파일과 드래그앤드롭

입력지원 범위준비 방법
폴더하위 폴더를 포함한 파일 목록한 작업의 원본 이미지 폴더를 각 영역에 하나씩 지정하는 방식 권장
ZIP내부 파일을 메모리에서 읽어 비교암호 없는 일반 ZIP. 디스크에 압축을 풀거나 내부 파일을 덮어쓰지 않음
이미지 여러 개PNG / TIF / TIFF / JPG / JPEG / JPE각 영역에 여러 파일을 함께 드롭하거나 파일 선택창에서 다중 선택
여러 폴더·ZIP 혼합입력 목록으로 처리묶음 이름이 상대 경로에 포함될 수 있으므로 대응 이름을 상세에서 확인
PNG1/2/4/8/16비트, 그레이·RGB·RGBA·팔레트 등APNG 애니메이션은 미지원
TIFF지원 코덱으로 해독 가능한 원본 비트 수와 다중 페이지지원되지 않는 압축·구조는 오류 또는 미지원으로 표시
JPEG일반 8비트 그레이·RGB·CMYK12비트 등 고정밀 JPEG는 미지원

드롭 영역의 빈 부분이나 안내 문구를 눌러도 파일 선택창을 열 수 있습니다. ‘비우기’는 해당 영역의 선택만 해제합니다. 검사 중에는 입력 영역과 설정이 잠기며, 드롭으로 실행 중인 검사의 입력을 교체할 수 없습니다.

폴더와 ZIP 안의 보조 파일도 목록에 들어옵니다. preview.png 같은 미리보기는 유효한 PNG이므로 일반 이미지와 같이 처리합니다. run.gcode, 텍스트, 장비 전용 CTB·PHOTON 등은 미지원으로 표시합니다. 일반 이미지 개수와 실제 숫자 레이어 개수를 구분하세요.

확인 사항

중복된 ZIP 경로와 한 묶음 안의 대소문자 충돌은 모호한 입력으로 처리합니다. 이름이 비슷하다는 이유로 임의의 파일을 골라 덮어쓰거나 대응시키지 않습니다.

4. 짝짓기 기준 — 경로와 자연 정렬

기준짝을 만드는 방법적절한 상황
상대 경로 / 파일명기준 폴더·ZIP 내부의 하위 경로와 파일명이 같은 항목끼리 연결복사·치환 전후처럼 같은 파일명을 유지한 묶음
레이어 순서 (숫자 정렬)각 묶음을 자연 정렬한 뒤 첫 항목끼리, 두 번째 항목끼리 순서대로 연결파일명 접두사 등이 다르지만 순서가 대응하는 묶음

자연 정렬에서는 layer2.png가 layer10.png보다 먼저입니다. 순서 모드는 숫자를 추출하여 ‘같은 층 번호’를 찾는 기능이 아닙니다. 번호 누락·추가가 있으면 그 뒤의 짝이 밀릴 수 있으며, 미리보기 등 이미지 보조 항목도 정렬과 짝짓기에 영향을 줄 수 있습니다.

A: 1.png, 2.png, 3.png
B: 1.png,        3.png

경로 모드: A 1 ↔ B 1 / A 2만 있음 / A 3 ↔ B 3
순서 모드: A 1 ↔ B 1 / A 2 ↔ B 3 / A 3만 있음

경로 모드에서는 확장자와 이름의 대소문자도 원본과 맞추는 것이 좋습니다. 1.png와 1.tiff처럼 이름이 다르면 같은 층이라고 자동으로 연결하지 않습니다. 한 ZIP의 모든 항목에 공통인 최상위 폴더가 있으면 포장용 폴더로 보고 제외할 수 있으며, 이 처리는 상세의 묶음 검사 참고와 JSON warnings에 기록합니다.

확인 사항

번호 시작이 0인지 1인지, 중간 번호가 빠졌는지를 이 탭이 완전한 스택 규칙으로 강제 검증하지는 않습니다. 실제 마지막 층과 입력 범위를 먼저 확인한 뒤 알맞은 짝짓기 기준을 선택하세요.

5. 빠른 검사와 정밀 옵션

화면의 기본값은 빠른 검사입니다. 각 파일 전체의 SHA-256을 계산하고 헤더·구조를 확인합니다. 대응 파일의 전체 해시가 같으면 같은 파일 내용이라는 근거로 픽셀 일치를 확인하고, 큰 이미지의 전체 픽셀 해독은 생략합니다. ZIP 자체의 해시가 아니라 ZIP 안의 각 파일 내용을 비교합니다.

입력 상태기본 빠른 검사정밀 옵션을 켠 검사
양쪽 전체 파일 해시가 같음헤더·구조 확인 후 파일 바이트로 일치 확인전체 픽셀 해독 검증. 이미 성공한 동일 내용의 해독 결과는 재사용할 수 있음
양쪽 전체 파일 해시가 다름양쪽 원본 픽셀을 해독하여 픽셀·검사 속성 비교같은 방식으로 전체 픽셀 비교
한쪽에만 있는 파일존재 여부와 헤더·구조 확인존재하는 파일의 전체 픽셀 해독도 검증
손상·미지원 형식·제한 초과확인 가능한 단계에서 오류 또는 미지원 표시오류 또는 미지원 표시. 불완전한 해독을 일치로 처리하지 않음
확인 사항

같은 바이트는 두 파일 사이의 일치를 증명하지만 두 파일이 함께 같은 방식으로 손상되었을 가능성까지 제거하지는 않습니다. 빠른 검사에서 PNG CRC 등 구조 검사가 통과해도 픽셀 압축 데이터 전체의 정상 해독을 보장하지 않습니다. 파일 자체의 무결성 확인이 목적이면 ‘정밀: 같은 파일도 전체 픽셀 해독’을 켜세요.

검사 상세에는 파일 바이트로 확인했는지, 전체 픽셀을 해독했는지가 표시됩니다. JSON의 pixel_comparison과 각 파일의 decode_validation에도 검사 방식이 남습니다. 정밀 옵션을 바꾸면 현재 결과가 지워지므로 옵션을 선택한 뒤 다시 실행합니다.

6. 위치 차이와 원본 픽셀 좌표

같은 크기의 그림이라도 형상이 오른쪽·왼쪽·위·아래로 이동하여 원본 좌표의 픽셀이 달라지면 픽셀 차이로 검출됩니다. 형상 개수, 흰 픽셀 총수, 외관이 비슷하다는 이유로 일치시키지 않습니다. 두 그림을 자동으로 정렬·이동·크기 변경해 맞춘 뒤 비교하지도 않습니다.

빠른 검사에서도 실제 위치가 달라 파일 내용이 바뀌면 전체 해시가 달라집니다. 그 쌍은 원본 비트 수의 전체 픽셀 비교로 넘어갑니다. 따라서 빠른 모드라는 이유로 좌표 차이를 무시하거나 작은 썸네일만 비교하지 않습니다.

참고

픽셀 차이는 명도·색상·형상 변화·위치 이동 중 하나 이상이 다르다는 뜻입니다. 이 탭은 이동량이나 원인, 제품별 ID를 자동으로 계산하지 않습니다. 위치 변화량이나 인접층의 이동 신호를 분석하려면 해당 목적의 ‘슬라이싱 위치 검사’ 결과와 원본을 함께 검토하세요.

JPEG는 손실 압축 형식입니다. 같은 원본 그림을 다시 저장해도 디코딩한 픽셀 값이 달라질 수 있습니다. 이 탭은 유사도 점수나 허용 오차를 사용하지 않으므로 작은 명도 차이도 픽셀 차이로 표시합니다.

7. 해상도·비트 수·채널·DPI의 의미

검사 항목표시와 의미확인할 점
해상도가로 픽셀 × 세로 픽셀파일의 픽셀 격자 크기. DPI와 구분
채널당 비트 수예: 8, 1616비트 원본을 8비트로 줄여 비교하지 않음
채널 수예: 그레이 1, RGB 3, RGBA 4투명도·색상 모드가 다르면 별도 차이가 될 수 있음
픽셀당 비트 수채널 비트 수의 합RGB16은 일반적으로 16 × 3 = 48비트/픽셀
실제 파일 형식파일 내용으로 확인한 PNG / TIFF / JPEG확장자 이름만 보고 형식을 결정하지 않음
프레임 / 페이지 수다중 페이지 TIFF 등을 구성하는 이미지 수전체 페이지를 검사하며 표의 해상도·비트 수는 첫 프레임 기준
색상 해석팔레트·투명도·방향·ICC 등 검사 대상 정보같은 숫자 샘플이어도 해석이 다르면 표시가 달라질 수 있음
DPI (참고)파일에 기록된 해상도 메타데이터장비의 실제 XY 픽셀 크기를 자동 보증하지 않으며 별도 DPI 입력칸 없음
파일 크기 / SHA-256압축·메타데이터를 포함한 원본 파일 전체픽셀이 같아도 이 값은 다를 수 있음

정밀 비교는 전체 프레임의 원본 샘플과 검사 대상 색상 해석을 사용합니다. 여러 페이지의 크기나 비트 수가 서로 다른 TIFF는 첫 페이지 요약만으로 판단하지 말고 검사 상세의 전체 프레임 데이터를 확인합니다. 모든 촬영일·장비별 태그를 필드별로 해석하는 기능은 제공하지 않으며, 해석하지 않은 태그의 변화도 파일 바이트 차이에는 반영됩니다.

DPI만 변경하면 픽셀·검사 속성은 같고 파일 바이트만 달라질 수 있습니다. 물리 크기가 필요하면 실제 XY DPI가 확인되었을 때만 ‘픽셀 수 × 25.4 ÷ DPI’로 계산합니다. 예를 들어 실제 가로·세로가 모두 400 DPI라면 5985 × 7875픽셀 전체 캔버스는 약 380.05 × 500.06 mm이고 1픽셀은 0.0635 mm입니다.

확인 사항

위 수치는 400 DPI라는 전제가 맞을 때의 캔버스 환산 예입니다. 그 안에 놓인 제품 하나의 크기나 제품 간 간격을 뜻하지 않으며, 모든 제품을 6 mm로 가정하지 않습니다. 실제 제품 크기는 해당 형상의 픽셀 범위와 장비 설정을 별도로 확인해야 합니다.

11. 이미지 미리보기의 표시 범위

행을 선택한 뒤 ‘이미지 미리보기’ 탭을 열면 A/B 파일의 첫 프레임을 화면 크기로 줄여 표시합니다. TIFF의 두 번째 이후 페이지는 미리보기 대상이 아니지만 실제 비교에는 포함됩니다. 미리보기 탭을 열기 전에는 자동으로 모든 이미지를 해독해 표시하지 않습니다.

16비트·정수·부동소수점 그레이 이미지는 축소한 영상의 밝기 범위를 화면용 8비트로 정규화합니다. 두 파일을 각각 정규화하므로 원본 명도 범위가 달라도 미리보기는 비슷해 보일 수 있고, 일정한 값만 있는 영상은 표시가 어둡게 보일 수 있습니다. 방향 정보가 있으면 화면 표시를 위해 반영할 수 있습니다.

확인 사항

미리보기는 판정에 사용하지 않습니다. 작은 하위 비트 차이, 한 픽셀 이동, 미세한 색상 차이는 축소 화면에서 보이지 않을 수 있습니다. 표의 픽셀 일치와 검사 상세를 우선하고, 필요한 경우 원본 해상도를 별도 이미지 도구로 확인하세요.

창이나 상세 영역 크기에 맞게 썸네일을 다시 만듭니다. 이미지가 너무 크거나 ZIP 내부 파일이 미리보기 제한을 넘거나 표시용 해독이 실패하면 ‘미리보기 생략’ 이유가 나옵니다. 미리보기를 표시하지 못했다는 사실과 해당 행의 검사 판정은 구분해 읽습니다.

12. 사용 예시 — 위치·16비트·압축 차이

예시 1. 32개 격자의 개수는 같지만 위치가 이동한 경우

A와 B에 같은 8열×4행, 총 32개 형상이 있고 B만 전체적으로 오른쪽 4픽셀 이동했다고 가정합니다. 캔버스 크기·형상 개수·흰 픽셀 총수가 같아도 원본 좌표의 픽셀이 달라지므로 ‘픽셀 일치: 다름’으로 표시됩니다. 빠른 모드에서도 파일 해시가 달라진 쌍은 전체 픽셀 비교를 수행합니다. 실제 XY 해상도가 400 DPI라면 4픽셀은 0.254 mm에 해당하지만, 프로그램이 이 이동량을 자동으로 계측해 주는 것은 아닙니다.

예시 2. 16비트 그레이의 하위 비트만 다른 경우

같은 좌표의 원본 값이 A에서는 0x1200(4608), B에서는 0x1201(4609)인 경우입니다. 두 파일은 모두 16비트이고 8비트 썸네일은 같아 보일 수 있지만 원본 샘플이 다르므로 픽셀 차이로 표시됩니다. 비트 수가 같다는 것과 픽셀 값이 같다는 것은 별개의 조건입니다.

예시 3. PNG 압축률이나 참고 메타데이터만 다른 경우

원본 픽셀과 검사 속성이 같은 PNG를 압축 설정만 바꿔 저장하거나 참고용 텍스트를 추가하면 전체 파일 바이트가 달라질 수 있습니다. 해당 행은 ‘차이 있음’, ‘픽셀 일치: 같음’, ‘바이트 일치: 다름’이며 상세에는 파일 바이트 차이가 나옵니다. 전체의 차이가 이런 항목뿐이면 ‘픽셀·속성 일치 · 파일 바이트에 차이가 있습니다’로 안내합니다. 실제 형식·비트 수·색상 해석까지 바뀐 경우에는 이 예와 다른 차이가 함께 표시될 수 있습니다.

13. 실제 묶음 예시 — M1 치환

2026년 10월 23일 확인한 ‘M1 치환’ 폴더와 ‘M1 치환.zip’을 예로 설명합니다. A에 폴더, B에 ZIP을 선택하고 경로 모드로 비교한 결과입니다. 이 수치는 해당 입력 묶음에 관한 기록이며 다른 작업의 정상 층 수를 정하는 기준이 아닙니다.

14. CSV·JSON 저장과 결과 보관

  1. 완료 또는 중지 결과가 표시된 뒤 ‘JSON 저장’을 눌러 보관 경로와 파일명을 정합니다.
  2. 표 형태의 검토가 필요하면 ‘CSV 저장’도 함께 실행합니다. CSV는 한글을 Excel에서 읽기 쉽도록 UTF-8 BOM으로 저장합니다.
  3. 저장 완료 경로를 확인합니다. 같은 이름의 파일을 선택하면 저장창의 덮어쓰기 확인을 주의해서 읽습니다.
  4. 원본 입력 범위와 A/B 방향, 짝짓기 기준, 빠른/정밀 여부를 함께 기록합니다. 중지된 결과라면 파일명에도 ‘부분’ 또는 ‘중지’를 구분해 둡니다.
형식보관되는 내용사용 목적
CSV파일명·상태·픽셀 일치·검사 방식·차이·오류와 A/B 메타데이터스프레드시트에서 행별 정리·검토. 일부 열의 상세 값은 JSON 문자열
JSON전체 요약·A/B 입력·짝짓기·중지 여부·경고·처리 시간·모든 행과 프레임검사 범위와 완료 상태를 보존하는 상세 기록

저장은 사용자가 선택한 보고서 파일만 생성합니다. 검사 자체가 입력 폴더에 결과 파일을 자동으로 덮어쓰거나 PNG·TIFF·JPEG·ZIP 내용을 변경하지 않습니다. 결과 표에 표시한 이미지 미리보기를 원본으로 다시 저장하는 기능도 아닙니다.

확인 사항

중지 후 저장은 완료된 항목의 부분 보고서입니다. CSV는 행 중심 형식이므로 중지 여부와 전체 요약을 확실히 보존하려면 JSON도 함께 저장하고 cancelled 값을 확인하세요. ‘행이 모두 일치’인 부분 CSV만으로 전체 묶음이 일치했다고 결론 내리지 않습니다.

15. 중지·재실행·종료

  1. 진행 중에는 탭의 ‘중지’ 또는 이 탭을 선택한 상태에서 통합 창의 ‘현재 작업 중단’을 누릅니다.
  2. 현재 파일 읽기나 디코딩 작업이 중단 가능한 지점에 도달할 때까지 기다립니다. 큰 이미지에서는 요청이 즉시 반영되지 않을 수 있습니다.
  3. ‘검사 중지’ 문구를 확인합니다. 아래에는 완료된 항목만 남고 처리 중이던 한 쌍은 포함되지 않을 수 있습니다.
  4. 필요하면 부분 결과임을 구분하여 저장합니다. 전체 결과가 필요하면 A/B 입력과 설정을 확인하고 ‘일치성 검사’를 다시 누릅니다.
  5. 통합 프로그램 종료 시에는 진행 작업 중단 안내를 읽고 정리를 기다립니다.

중지한 위치에서 이어 하는 기능은 없습니다. 재실행은 처음부터 새로 검사하며 현재 화면의 보고서를 새 결과로 교체합니다. 입력이나 설정을 변경하면 이전 보고서가 지워지므로 보관할 결과는 먼저 저장합니다.

확인 사항

검사 도중 외부 프로그램에서 원본 파일이나 ZIP을 수정·삭제하지 마세요. 입력 변경이 확인되면 오류로 표시하여 이전에 읽은 데이터만으로 전체 일치를 확정하지 않습니다.

16. 처리 제한과 속도·메모리

항목기본 제한 또는 처리 방식영향
개별 입력 파일최대 512 MiB제한 초과는 검사 오류로 표시될 수 있음
이미지 크기최대 100,000,000픽셀가로×세로 기준. 원본 채널 수와 자료형도 메모리에 영향
TIFF 페이지최대 10,000개지원 코덱과 일반 2D 슬라이스 구조 조건도 확인
ZIP 항목 수최대 100,000개보조 항목을 포함한 ZIP 목록 기준
ZIP 전체 해제 크기최대 8 GiB디스크에 실제 압축을 풀지는 않지만 메타데이터 제한 적용
ZIP 압축률항목별 최대 2,000배과도한 압축 항목은 오류로 안내할 수 있음
미리보기첫 프레임만 축소, 큰 파일·이미지는 생략 가능ZIP 내 개별 파일이 128 MiB를 넘으면 표시를 생략

압축 파일 크기가 작아도 원본 픽셀을 펼칠 때 메모리가 필요합니다. 예를 들어 5985×7875 그레이 8비트의 원본 샘플은 약 45 MiB, 같은 크기의 RGB16은 약 270 MiB입니다. 디코더·배열 복사·해시·표시 버퍼에 메모리가 추가될 수 있으므로 압축 용량만으로 처리 가능 여부를 판단하지 않습니다.

같은 PC에서 실제 M1 폴더 1,602장과 ZIP 1,825항목을 빠른 모드로 검사한 독립 실행 파일의 실측은 약 4.5초였습니다. 이미 파일시스템을 읽어 둔 조건에서의 한 번의 측정값으로, 통합 프로그램·다른 PC에서 같은 시간을 보장하지 않습니다. 저장장치, 메모리, 이미지 크기·형식, 서로 다른 파일의 수, 정밀 옵션에 따라 달라집니다.

기본 빠른 검사는 바이트가 같은 큰 이미지의 불필요한 해독을 줄입니다. 정밀 옵션은 정상 해독 검증의 범위를 넓히므로 오래 걸릴 수 있습니다. 네이티브 PNG 코덱과 동일 내용의 성공한 해독 결과 재사용은 원본 정밀도를 유지하며, 축소 이미지로 판정을 대체하지 않습니다.

17. 문제 해결

증상확인할 원인조치
드롭해도 입력이 바뀌지 않음검사 진행 중 입력 잠금 또는 드롭 모듈 문제검사 종료를 기다리거나 ‘폴더 선택’·‘파일 / ZIP 선택’ 사용
모든 파일이 A/B에만 있음하위 경로·접두사·확장자·대소문자 차이양쪽 상대 경로를 확인하고 필요할 때만 순서 모드 선택
순서 모드에서 뒤쪽이 연속으로 다름중간 파일 누락·추가 또는 미리보기 혼입짝으로 표시된 이름을 확인하고 경로 모드로 재검사
그림은 같은데 ‘차이 있음’압축·참고 메타데이터·실제 형식·비트 수 차이픽셀과 바이트 열, 상세의 발견된 차이를 구분
픽셀은 같은데 형식이 다름같은 샘플을 PNG/TIFF 등으로 저장일치가 필요한 기준에 맞게 형식 차이를 검토
미지원 1개가 남음run.gcode·텍스트·장비 전용 형식 등이 포함파일명과 실제 형식을 확인. 이미지 수와 분리하여 해석
확장자와 실제 형식이 다르다는 주의파일명만 바꾸었거나 잘못 내보냄원본 파일 내용을 확인. 이름만 바꿔 형식을 변환하지 않기
CRC·잘림·해독 오류손상된 PNG·JPEG·TIFF 또는 코덱 미지원원본을 다시 복사·내보내고 정밀 검사. 오류 파일을 일치로 취급하지 않기
미리보기가 어둡거나 같아 보임축소·그레이 정규화·일정 명도·하위 비트 차이픽셀 판정과 상세 우선, 원본 해상도로 확인
미리보기 생략이미지·ZIP 항목 크기 또는 표시용 해독 제한생략 이유와 실제 검사 상태를 따로 확인
저장 버튼이 비활성화됨아직 검사 전이거나 입력·설정이 변경됨현재 조건으로 다시 검사
표에 결과가 없는데 항목 수는 있음검색어 또는 필터 적용검색어를 지우고 ‘전체’ 선택
느리거나 중지 반영이 늦음정밀 모드·고해상도·다른 파일 다수·저장장치 지연현재 파일·경과 시간을 확인하고 디코딩 종료를 기다림. 목적에 맞는 모드로 재검사
검사 도중 입력 변경 오류외부 프로그램에서 원본·ZIP을 변경파일 변경 작업을 끝내고 고정된 입력으로 재실행

오류를 확인할 때는 A/B 입력 종류, 파일명 예시, 이미지 크기·형식·비트 수, 짝짓기 기준, 정밀 옵션, 해당 행의 오류 문구를 함께 기록합니다. 통합 창 자체의 실행 오류는 실행 패키지의 logs/errors.log도 확인할 수 있습니다.

18. 용어와 작업 완료 확인

용어설명
원본 샘플이미지를 구성하는 각 채널의 저장 정밀도에 따른 값
픽셀 일치같은 좌표의 원본 샘플과 검사 대상 색상 해석이 같음
파일 바이트 일치파일 전체 SHA-256이 같음. 압축·메타데이터도 포함
자연 정렬문자열 속 숫자를 숫자 크기로 정렬하되 항목은 순서대로 대응하는 방식
전체 픽셀 해독압축된 영상 데이터를 원본 정밀도의 픽셀 값으로 펼쳐 확인하는 처리
부분 결과중지 전에 완료한 항목만 포함한 보고서
  • A/B가 의도한 두 묶음이며 실제 총 층 수와 선택 범위가 맞다.
  • 경로 또는 순서로 만든 파일 짝이 올바르다.
  • 빠른 비교와 파일 자체 무결성 검증의 목적을 구분해 정밀 옵션을 선택했다.
  • 픽셀·속성·바이트 차이, 누락, 오류·미지원 항목을 각각 검토했다.
  • 미리보기의 축소·정규화를 판정 근거로 오해하지 않았다.
  • 검사가 끝났는지 확인하고, 중지 결과는 부분 결과로 구분했다.
  • 필요한 CSV와 완료 상태가 포함된 JSON을 저장했다.
