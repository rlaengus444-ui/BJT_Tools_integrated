BJT 통합 작업 도구 1.6.2 — 사용 안내
문서 갱신: 2026-10-26 (Asia/Seoul)

실행 — Python 설치가 없는 PC
- 1.6.2 EXE 배포 파일을 원하는 폴더에 전체 압축 해제합니다. 파일이 여러 ZIP으로 나뉜 배포본이면 배포 페이지의 합치기/해제 안내를 따르세요.
- 복원 후 BJT_통합프로그램_1.6.2_EXE 폴더의 BJT_통합프로그램.exe를 사용합니다.
- BJT_통합프로그램.exe를 실행합니다. 처음 실행할 때 계산 라이브러리 로딩에 시간이 걸릴 수 있습니다.
- EXE 옆의 _internal 폴더를 함께 유지하세요. EXE만 꺼내 복사하면 실행되지 않습니다.
- Python·Excel·.NET 설치와 pip 설치 없이 실행합니다. Windows 10·11 64비트용입니다.
- BJT_명령줄.exe는 콘솔 진단/명령줄 작업용이며 일반 사용은 GUI EXE를 엽니다.
- 사용자 설정·오류/Numba 캐시는 사용자 로컬 앱 데이터 폴더에 저장됩니다.

- 폴더 버전: BJT_통합도구.pyw 또는 BJT_Tools_통합.pyw를 실행합니다.
- 명령줄: python run_suite.py

- .pyw/.py/.cmd는 Python이 필요한 소스판입니다. Python이 없는 PC에는 위의 EXE 배포판을 사용하세요.

4. 슬라이싱 교체: 범위 교체·백업·교체 후 전체 번호/형식 자동 검사·실패 복구.
5. 슬라이싱 위치 검사: 치환 경계·인접층 위치 이동 검사.
6. 열·산소 확산: 3D 열전달/O2, 보정·설정·CSV·3D 재생.
7. 슬라이싱 일치성 검사: 두 폴더/ZIP/이미지 묶음의 픽셀·위치·해상도·비트·실제 형식·파일 비교.
8. 번호 복제·누락 검사: 번호 범위로 파일 복제 및 예상 번호의 누락/중복/범위 밖 항목 검사.
   BJ Tools의 별도 이미지 속성 일치 검사 화면은 중복을 피하기 위해 포함하지 않았습니다.
9. 시퀀스별 Z값: M1 Z축 수식의 레이어별 프린팅·이동/피딩·리코팅 Z값 조회, 표 및 CSV.
10. M2 이미지 변환: 싱글·멀티 선택, 지정 해상도/DPI의 4비트 반전 TIFF/LZW 출력 및 형식 검사.
11. 치투 오브젝트 검사: CHITUBOX Basic 프로젝트의 겹침·표면 접촉·최소 간격을 검사하고 문제 쌍의 3D 배치 확인.

치투 오브젝트 검사 — 빠른 사용
   탭·시작 화면 카드·상단 도구 선택 목록에서 엽니다. 좁은 창에서는 상단 목록으로 11개 도구를 모두 선택할 수 있습니다.
1. ‘파일 선택’으로 .chitubox/.chitu 프로젝트 한 개 또는 배치 좌표를 유지한 개별 STL 여러 개를 선택합니다.
   개별 STL 묶음은 ‘STL 폴더’로 선택할 수도 있습니다. 폴더 바로 아래 .stl 파일만 읽습니다.
2. ‘최소 간격 (mm)’의 기본값은 0.0입니다. 1.5 mm가 필요하면 1.5를 입력합니다.
   표면 접촉은 최소 간격이 0이어도 항상 FAIL입니다. 부피 겹침·완전 포함도 FAIL입니다.
3. ‘검사 시작’을 누릅니다. 파일 읽기부터 준비·검증·쌍 검사까지 진행 상태를 표시합니다.
   PASS / FAIL / 판정 불가와 실행 완료·판정 완료 여부를 함께 확인합니다.
   실행 절차가 끝나도 잘못된 메쉬가 있으면 전체 판정은 불가일 수 있습니다.
4. 표에서 A/B 이름과 인덱스, 간격과 원인을 확인합니다. ‘전체 쌍 표시’를 켜면 통과한 쌍도 표시합니다.
   숫자 mm는 실제 최단 거리이며 ‘≥ X mm’는 최소한 X mm 떨어져 있음을 확인한 하한입니다.
5. ‘3D 배치 보기’로 HTML 저장 위치를 정하면 브라우저에서 배치가 열립니다.
   문제 쌍을 선택하면 A는 빨강, B는 주황입니다. 회전·확대·나머지 숨김·최근접 거리선을 사용할 수 있습니다.
   총 삼각형 20만/정점 12만의 표시 예산 안에서 작은 문제 쌍의 실제 메쉬를 우선 표시합니다.
   초과하는 큰 모델은 안내와 함께 경계 상자 선으로 표시합니다. 원본 정밀도의 검사값·거리선은 유지합니다.
6. ‘JSON 저장’으로 설정, 실행 완료/판정 완료, 오류와 쌍별 정확한 거리 또는 거리 하한을 기록합니다.
   HTML은 인터넷 없이 열립니다. processing_completed=true여도 complete=false이면 전체 PASS가 아닙니다.
7. 입력이나 간격을 바꾸면 이전 결과가 무효화됩니다. 새 조건으로 다시 검사하세요.
8. 실제 Basic 매직 0xAB231243 형식을 읽습니다. .ctb 슬라이스, .ctp Pro, 별도 네이티브 서포트/래프트 블록은 지원하지 않습니다.
   다른 형식은 CHITUBOX에서 모델·서포트의 배치 좌표와 mm 단위를 유지한 개별 STL로 내보내세요.
9. 모든 모델을 합친 STL은 원래 오브젝트 구분을 잃습니다. 내보낼 때 각 모델을 원점/가운데로 이동하지 마세요.
10. 정확한 CAD 연결면 정리 범위 밖의 열린 메쉬·퇴화 삼각형·잘못된 면·계산 실패는 판정 불가입니다.
    원본 모델을 임의로 수리하거나 움직이지 않습니다.
    유효하지 않은 모델이 있으면 최소 간격은 유효한 모델 사이의 값이며 파일 전체 최소 간격이 아닙니다.
11. 읽기·나뉜 메쉬 검증 단계에서도 ‘중단’ 또는 상단 ‘현재 작업 중단’을 사용할 수 있습니다.
    네이티브 계산은 반환 후 반영될 수 있습니다. 중단 결과나 판정 불가를 합격으로 사용하지 않습니다.
12. 원본 프로젝트를 수정하지 않습니다. 결과는 입력과 다른 경로에 저장합니다.

치투 연결면 정리 — 1.6.2
- 일부 CAD 카메라 모델의 정확히 일직선인 연결면은 원본 좌표와 표면을 유지하는 검사용 복사본으로 정리합니다.
  정리 후 닫힌 표면·일관된 면 방향·양의 부피 조건을 다시 통과해야 검사에 사용합니다.
- 일반 유효 모델의 검사 방식은 유지합니다. 열린 메쉬·비다양체·같은 정점 번호를 반복한 삼각형 등은 판정 불가로 남습니다.
- 정리된 모델의 개수와 안내가 GUI·명령줄·3D HTML에 표시됩니다. 카메라 예제 파일은 ‘형상 유지 정리 2개’입니다.
  JSON objects의 normalization에 좌표/표면 보존과 정리 내역, source_errors에 원래 오류를 기록합니다.
- 260928-M1-1__.chitubox의 49개 모델·1,176쌍은 요구 간격 0/1 mm에서 전체 PASS입니다.
  요구 1.5 mm에서는 [5]↔[6]이 1.4999923706054688 mm로 미달하며, 요구 2 mm에서는 네 쌍이 미달합니다.
- 위 정확한 연결면 정리는 자동 구멍 메우기나 허용오차 좌표 병합이 아닙니다. 자세한 지원 범위는 F1을 확인하세요.

치투 대용량 검사 — 유지 기능
- 원본 좌표를 유지하면서 부분 읽기, 같은 형상 재사용, 나뉜 검증으로 메모리와 반복 작업을 줄였습니다.
- 삼각형 100만 개 초과 입력과 형상 유지 정리로 새롭게 판정 가능한 모델 관련 쌍에서는
  충분히 떨어진 쌍의 거리 하한으로 간격 충족을 확인할 수 있습니다.
  기존부터 유효했던 소규모 모델 사이의 쌍은 기존처럼 정확한 거리를 계산합니다.
  요구 간격에 가까운 쌍, 모든 Fail 쌍 및 가장 가까운 유효 쌍은 실제 표면을 정밀 계산합니다.
- JSON의 distance_mode='certified-clearance'와 distance_is_exact로 거리 계산 범위를 구분합니다.
  distance_mm=null과 distance_lower_bound_mm는 미측정·판정 실패가 아니라 하한을 확인한 통과 쌍일 수 있습니다.
  쌍의 status와 오류를 함께 읽으세요. pair_distances_complete는 모든 쌍의 정확한 거리 계산 여부입니다.
- closest_pair_scope='valid_objects'이면 최소 간격은 유효 모델 범위의 값입니다.
  closest_distance_is_global=false인 값을 파일 전체 최소 간격으로 사용하지 마세요.
- 실측 시간·메모리와 반복 검증의 범위는 최신 1.6.2 검증 보고서를 확인하세요.

새 일치성 검사 — 빠른 사용
1. A에 기준, B에 비교 묶음을 놓습니다. 폴더·ZIP·여러 이미지를 드래그하거나 선택합니다.
2. 같은 상대 경로/파일명 또는 숫자 자연 정렬 순서로 짝짓기를 선택합니다.
3. 기본 빠른 검사에서는 파일 전체 SHA-256이 같으면 바이트 일치로 픽셀 일치를 확인합니다.
   해상도/용량만 같다고 픽셀 일치로 판정하지 않습니다. 위치가 달라지면 픽셀도 달라집니다.
4. 파일 바이트가 다르면 원본 비트 수로 각 좌표의 픽셀을 해독하고 비교합니다.
5. 같은 파일까지 해독하여 손상 검사하려면 '정밀: 같은 파일도 전체 픽셀 해독'을 켭니다.
6. 빠른 검사의 헤더/구조 확인은 전체 픽셀 손상 검사와 다릅니다. 동일하게 손상된 두 파일도
   바이트 자체는 같을 수 있습니다. 결과의 decode_validation / pixel_comparison을 확인하세요.
7. TIFF는 전체 페이지/프레임을 검사합니다. 미리보기는 첫 프레임의 화면용 축소본입니다.
8. CSV/JSON으로 전체 결과를 저장할 수 있습니다. 중단된 결과는 부분 결과입니다.
9. PNG/TIFF/JPEG가 대상이며 APNG·장비 전용 형식·G-code 등은 미지원으로 표시합니다.
   preview.png 같은 미리보기도 일반 PNG 항목으로 포함합니다.

슬라이싱 교체 — 자동 최종 검사
1. A는 교체할 대상 폴더, B는 복사할 소스 폴더입니다. 두 범위의 개수가 같아야 합니다.
2. 대응 파일 검사 → A의 대상 구간 백업 → 교체 → A 전체 최종 검사를 자동 진행합니다.
3. A 바로 아래 숫자 이름의 PNG/TIFF/JPEG/BMP 전체를 검사합니다. preview 등 비숫자 이미지와
   하위 폴더/백업 폴더는 제외합니다. 최소 번호~최대 번호 사이 누락과 중복을 확인합니다.
4. 해상도, 원본 비트 수/채널, 확장자와 실제 형식, TIFF 전체 프레임 구조가 같아야 통과합니다.
   RGB 8비트(24 bit/pixel)와 RGB 16비트(48 bit/pixel)를 구분합니다. DPI는 비교하지 않습니다.
5. 각 층의 이미지 내용이 서로 같아야 한다는 뜻은 아닙니다. 이미지 전체를 해독해 손상을 확인합니다.
6. 로그에 기준 파일/형식, 전체 검사 수와 진행을 표시합니다. 최종 검사 실패 시 교체 구간을
   백업으로 복원합니다. 원래부터 있던 누락/다른 구간의 이상까지 새로 고치지는 않습니다.

번호 복제·누락 검사 — 빠른 사용
1. '번호 파일 복제'에서 원본 파일과 출력 폴더, Min/Max를 설정합니다.
2. 10~20이면 양 끝을 포함한 11개 파일을 원본 확장자로 생성합니다. 이미지 재압축은 하지 않습니다.
3. 충돌 기본값은 건너뛰기입니다. 덮어쓰기 또는 _1, _2 이름 변경을 선택할 수 있습니다.
4. 덮어쓰기는 기존 대상 파일을 교체하며 자동 백업/전체 작업 롤백을 제공하지 않습니다.
   원본과 대상이 같은 파일이면 보호하며, 이름 변경 정책에서는 별도 사본을 생성합니다.
5. 출력 폴더를 비우면 원본 폴더를 사용하므로 실제 경로와 충돌 정책을 확인하세요.
6. 누락 검사는 대상 폴더의 바로 아래 파일만 대상으로 하며 하위 폴더는 재귀 검색하지 않습니다.
7. 파일명 앞의 숫자를 번호로 읽습니다. 015.png와 15_1.png는 모두 번호 15로 인식합니다.
8. 예: 1.png, 2.png, 4.png, 예상 1~5 → 누락 3, 5. 예상 범위를 모두 비우면 목록만 조사합니다.
9. 파일을 이미지로 해독하지 않으므로 큰 슬라이싱 폴더도 번호만 빠르게 조사합니다.
10. 작업 중 중단하면 완료된 복제 파일은 남으며, 결과는 부분 완료로 표시됩니다.

시퀀스별 Z값 — 빠른 사용
1. 초기 Z 364, 이동/피딩 하강량 0.6, 리코팅 상승량 0.5가 원본 기본값입니다.
2. 레이어 간격 0.1과 이동 계산의 +0.1 보정은 M1 원본 수식대로 고정합니다.
3. n층: 프린팅=초기 Z−(n−1)×0.1, 이동/피딩=프린팅−하강량+0.1,
   리코팅=이동/피딩+상승량. 입력에 따른 음수도 그대로 표시하며 자동 제한하지 않습니다.
4. 레이어 한 개를 조회하거나, 시작/끝 번호로 표를 계산합니다. 기본 범위는 1~3543입니다.
5. 표는 200행씩 페이지를 넘깁니다. CSV는 화면의 현재 페이지만이 아니라 전체 선택 범위입니다.
6. CSV는 Excel에서 한글이 보이도록 UTF-8 BOM으로 저장합니다. 취소/실패하면 기존 CSV를 보존합니다.
7. 설정/범위를 수정하면 이전 표를 무효화하므로 다시 계산합니다. 조회 레이어만 바꾸면 표는 유지됩니다.
8. 이 기능은 수식 계산이며 장비 이동 명령을 실행하지 않습니다. 원본 XLSM과 Excel은 실행에 필요 없습니다.

M2 이미지 변환 — 빠른 사용
1. 모드 선택: 싱글=8504×6614px/400×400DPI, 멀티=8504×13228px/400×800DPI.
2. 두 모드 모두 입력 한 장마다 TIFF 한 장을 만듭니다. 원본처럼 전체 크기로 늘려 채우며 비율 유지/여백/자르기를 하지 않습니다.
3. 원본과 같은 GDI+ 리사이즈 → 4비트 16색 팔레트 → 색상 반전 → TIFF LZW 순서를 사용합니다.
   16색은 원본 VGA 팔레트이며 16단계 회색조가 아닙니다. 투명 입력도 원본 방식으로 처리됩니다.
4. PNG/JPG/JPEG/BMP/TIF/TIFF를 추가하거나 폴더/이미지를 드래그합니다. ZIP은 지원하지 않습니다.
   폴더 바로 아래 이미지는 숫자 자연 정렬로 추가하며 하위 폴더는 포함하지 않습니다.
5. 목록 위/아래 이동으로 순서를 확정합니다. 목록 순서가 001.tif,002.tif,... 번호 순서입니다.
   시작 번호와 최소 자릿수를 조절할 수 있습니다. 기본은 원본과 같은 1번/3자리입니다.
6. 출력 폴더와 충돌 처리를 확인합니다. 기본 건너뛰기는 기존 파일을 갱신하지 않습니다.
   덮어쓰기는 기존 결과를 교체합니다. 출력이 어느 입력 원본과라도 겹치면 시작/저장을 차단합니다.
7. 변환을 시작하면 입력을 잠그고 순서대로 처리합니다. 이미지 하나씩 완전히 저장한 뒤
   해상도·DPI·실제 TIFF 형식·4비트 팔레트·LZW·1프레임인지 검사하고 최종 이름으로 저장합니다.
8. 손상/지원 불가 등 첫 오류에서 후속 처리를 멈춥니다. 변환/건너뜀/오류 수와 JSON/TXT 보고서를 확인하세요.
9. 중단은 현재 네이티브 변환 단계가 반환된 뒤 반영될 수 있습니다. 작성 중 임시 파일은 지우고
   이미 완료된 TIFF는 남깁니다. 전체 배치 롤백/자동 백업은 제공하지 않습니다.
10. 여러 프레임 TIFF는 원본 변환기처럼 첫 프레임만 변환합니다. 전체 프레임 비교는 일치성 검사 탭을 사용합니다.

통일된 화면
- 11개 탭의 버튼·입력창·표·로그와 글꼴에 공통 디자인을 적용했습니다.
- 탭의 입력 항목과 계산/파일 처리 방식, 그래프·이미지의 데이터 색상은 유지합니다.
- 배치 도구 좌측은 파일·배치 / 미리보기 / 조작 안내 탭으로 전환합니다.
- 좁은 창에서는 배치 상단 설정이 두 줄로 바뀌고, 출력·합성 버튼은 하단에 고정됩니다.

사용설명서
- 모든 도구 탭 상단의 '사용설명서 F1', 시작 화면의 '사용설명서', 상단 '사용 안내'로 엽니다.
- 도구의 초기 로딩 전에도 설명서를 열 수 있습니다.
- 목차·단계별 사용법·설정값·예시·출력·문제 해결을 제공합니다.

- '브라우저·인쇄': 오프라인 HTML 설명서를 열어 인쇄/PDF 저장합니다.
- manuals/index.html: 전체 설명서 목록. 단일 파일에도 모든 설명서가 포함됩니다.

작업 상태와 종료
- 탭을 바꾸어도 입력값과 작업 상태가 유지됩니다.
- 상단 '현재 작업 중단'은 현재 탭의 취소 가능한 작업에 중단을 요청합니다.
- 전체 창을 닫으면 실제 작업 스레드와 파일 정리가 끝날 때까지 기다립니다.
- 복제는 현재 파일 처리 후 중지하며, 이미 생성된 파일을 자동 삭제하지 않습니다.
- 기존 교체/복구 등 취소 불가능한 원본 작업은 완료까지 기다립니다.
- 여러 탭의 출력 폴더가 겹치지 않게 지정하세요.
- 기존 여섯 도구의 사용자 설정 저장 경로와 기본값은 변경하지 않았습니다.

보관과 검증
- 소스와 사용설명서는 폴더 버전에서 직접 읽을 수 있습니다.
- source_manifest.json은 포함 모듈과 검사 엔진의 SHA-256을 기록합니다.
- 통합_검증_보고서.txt 및 검증_결과 폴더에 검증 범위와 실제 결과가 있습니다.
- 검증의 통과는 기록된 입력·경로에 대한 확인이며 모든 실제 입력에 대한 무결점 보증은 아닙니다.
- 오류 기록은 logs/errors.log입니다. 사용자의 실제 입력/출력 파일은 별도 보관하세요.


이전 1.5판에서 관찰한 EXE 실행 환경 제한 — 이력
- 새 EXE 프로세스의 .zip 파일 생성/수정은 Windows 파일 API 단계에서 접근 거부(오류 5)를 받았습니다.
- 같은 폴더·같은 쓰기 옵션의 .png/.txt/.bin 생성·삭제는 정상이며, ZIP 내용에 관계없이 .zip 이름의 쓰기만 거부됐습니다.
- 기존 ZIP을 입력으로 읽는 비교는 실제 M1 폴더/ZIP 1825항목에서 오류 0, 약 3.25초였습니다.
- 이미지·STL·CSV 출력은 시험을 통과했습니다. 번호 복제에서 ZIP을 출력하는 등 ZIP 쓰기가 필요한 작업은 이 PC의 실행 환경 제한을 받을 수 있습니다.
- 보안제품/정책의 주체는 확정하지 않았고, 설정 변경이나 우회는 하지 않았습니다.
- 소스판의 122개 시험 통과와 EXE의 ZIP 생성/변경 시험에 대한 환경 제한을 구분해 기록했습니다.
