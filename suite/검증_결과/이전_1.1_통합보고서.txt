BJT 통합 작업 도구 — 구현 및 검증 보고서
작성일: 2026-10-21 (Asia/Seoul)

구현 방식
- 여섯 프로그램을 한 Tk 창의 독립 탭으로 통합했습니다.
- 외부의 여섯 원본 파일은 변경하지 않았습니다. sources 폴더에는 각각 byte-identical 사본을 포함합니다.
- 계산/파일 처리 함수를 재작성하지 않고 전체 원본 모듈을 끝까지 로드합니다.
  세 GUI 클래스(App/App/ThermalGUI)의 Tk 루트 기반 클래스만 AST로 프레임 어댑터에 연결합니다.
- 함수·클래스 본문 컴파일 결과 905개가 원본과 동일합니다.
  컴파일은 각 원본의 __future__ 설정을 그대로 따르도록 분리했습니다.
- 원본의 명령줄 진입점도 --tool로 실행할 수 있습니다.
- BJT의 내장 코어·Numba 모듈 등록·시작 인증·실제 소스 경로를 유지했습니다.
- 모든 GUI 생성은 메인 Tk 스레드에서 수행합니다. 모듈 준비는 별도 스레드에서 하여 창의 응답을 유지합니다.
- 배치 전역 단축키와 열 해석의 휠 바인딩을 탭별로 분리했습니다.
- 공통 종료 시 취소 신호를 보낸 뒤 실제 작업 스레드와 병렬 저장이 끝날 때까지 기다립니다.
  Arrange 내보내기의 UI 완료 통지와 실제 저장 종료 사이의 차이를 별도 추적으로 처리합니다.
- 원래 함수의 작업 내용은 유지하고 종료 추적용 래퍼만 추가했습니다.

실행 환경
- 기존 원본 BJT의 전용 Python 3.12.14 환경을 사용했습니다.
- 이 환경의 NumPy/SciPy/Pillow/Numba/VTK 등 원본 BJT 고정 버전을 재사용합니다.
- 다른 도구의 원본/통합 대조도 같은 실행 환경에서 수행했습니다.
- 전역 Python 패키지를 변경하거나 새로 설치하지 않았습니다.

검증 결과
1. 원본 무결성
   원래 파일 여섯 개와 포함된 파일 여섯 개의 SHA-256 일치.
   원본 파일이 바뀌면 로더가 무결성 오류로 알려 줍니다.

2. BJT 모델·격자·STL
   실제 파이프라인 6종 전부 원본과 일치.
   재구성/크롭·센터, 헥사 선격자 XYZ BMP, 사각 선격자 XY PNG,
   헥사 면격자 XYZ, 쉘 전용, STL 모델부터 전체 처리.
   최종 STL 전체 파일 SHA-256, 저장 이미지 이름/크기/모드/픽셀 SHA-256,
   메시 수치·보고 상태·미리보기·진행률까지 동일.
   원본 시작 인증 9개 통과(인접 큐브 12,282개 검사 포함).

3. 슬라이싱 도구 네 개
   21/21 시나리오 통과, 생성 자료 86/86 동일.
   범위 교체·백업·형식 거부·중간 실패 복구, 합성 4종/극성/매칭/패딩·크롭,
   배치 클리핑·숨김·회전·알파·NumPy/Pillow 경로·실제 STL 슬라이싱·캐시,
   5종 출력 형식·병렬 출력·길이 모드·취소, 위치 검사·ZIP·번호·캐시·보고서.
   출력 경로/자동 생성 시각/캐시 디렉터리 식별자 및 JSON 키 순서만 정규화했습니다.
   ZIP 컨테이너의 생성 시각은 바이트 대조에서 제외했습니다.

4. 열·산소 확산
   물리 계산 577개, GUI/내보내기 1467개, 합계 2044개 비교 통과.
   모든 SimulationResult 배열·수치, PSD/manual/calibrated/열·O2 경계와 검증 오류,
   취소·실측 보정, 43개 저장 입력·전체 프로파일, 위젯 내용, 차트·요약,
   두 3D 재생/이동/슬라이더, 설정 왕복·종료 정리까지 동일.
   22개 열 CSV와 UTF-8 BOM도 바이트 단위로 일치.

5. 통합 GUI 및 작업 수명
   여섯 GUI가 실제로 한 Tk 인터프리터/창 안의 7개 탭(시작+도구6)에 생성됨.
   비동기 준비 중 Tk 타이머 응답 유지, 활성 탭에서만 실제 배치 단축키 실행,
   휠 바인딩 삭제가 다른 탭의 바인딩을 제거하지 않음, 원본 종료 훅 호출 확인.
   취소 완료 통지를 먼저 받아도 병렬 저장이 남아 있으면 busy=True,
   파일 저장/스레드 종료 뒤 busy=False 확인.
   DnD 패키지 누락/네이티브 로딩 실패 2종 모두 일반 Tk 폴백 확인.
   통합 진입점에서 원본 위치 검사 --help 명령과 Python 환경 전환 성공.
   Python 구문 검사와 모든 원본 파일 무결성 검사 통과.

6. 탭별 사용설명서 (1.1 추가)
   도구 여섯 개에 총 71개 장의 사용설명서 제공.
   제품 개요·목차·빠른 시작·입력/설정 표·단계별 사용·연습 예시·출력·문제 해결 포함.
   각 탭과 시작 화면에서 열 수 있는 별도 창, F1, 목차 이동, 본문 검색,
   결과 순환·글자 크기·복사·오프라인 브라우저·인쇄/PDF 저장 진입 지원.
   JSON 원문 전체의 본문·표 셀이 네이티브/HTML 양쪽에 누락 없이 렌더링됨을 대조.
   고유 목차 링크·오프라인 자산·모듈 로딩 전 접근·도구 오류 후 버튼 유지 확인.
   검색 후 목차 동기화·장 이동·창 재사용/닫은 뒤 재열기·공통 종료 확인.
   실제 Chrome에서 여섯 문서의 검색·F3·빈 검색 초기화·인쇄 진입을 확인.
   화면에서 숨은 인쇄용 목차는 본문 검색에서 제외.
   여섯 도구를 다시 생성해 기존 전체 인터페이스와 탭 상단 설명서 버튼 유지 확인.
   계산·파일 처리 본문과 외부 원본 파일의 동일성도 다시 확인.

검증 범위
- 위 시나리오와 합성 입력으로 원본 대비 일치를 확인했습니다.
- 모든 가능한 실모델·장시간 대형 작업·운영 환경 조합을 실행한 것은 아닙니다.
- 통합 실행에서 새 계산 옵션이나 판정 기준을 추가하지 않았습니다.
- 기능을 검증한 사실과 모든 입력에서 완벽함을 증명했다는 주장은 구별합니다.

자료

- 별도 검증 자료 ZIP: 검증 스크립트와 상세 비교 보고서.
