1. 기능과 변환 결과

이미지 변환은 원본 M2 싱글·멀티 ImageConverter의 Windows GDI+ 처리 순서를 사용합니다. 입력 이미지를 지정한 픽셀 크기로 늘이거나 줄인 뒤 4비트 팔레트로 변환하고 팔레트 색상을 반전하여 LZW 압축 TIFF로 저장합니다. 입력 목록의 순서를 그대로 번호 파일명에 적용합니다.

작업동작확인할 내용
기본 규격과 사용자 설정싱글·멀티 기본값을 불러온 뒤 가로·세로 픽셀 및 X/Y DPI 수정현재 입력한 네 값이 실제 출력 규격
입력 순서목록의 위→아래 순서로 처리원본명 숫자를 출력 번호로 가져오지 않음
저장 형식4비트 16색 팔레트 TIFF · LZW회색 16단계 이미지와 다름
결과 검사새로 변환한 파일마다 TIFF 태그와 목표 규격 확인기존 파일을 건너뛰면 그 파일은 검사하지 않음
참고

이 기능은 이미지 크기와 색 표현을 바꾸는 변환입니다. 원본과 출력 픽셀·바이트가 같아야 하는 복제 기능이 아닙니다. 원본 입력 파일은 결과 저장 대상으로 사용하지 않도록 보호합니다.

2. 빠른 시작 — 세 이미지를 001~003.tif로 변환

  1. 통합 프로그램의 ‘이미지 변환’ 탭을 엽니다. ‘사용설명서 F1’ 또는 메인 창 F1로 이 설명서를 다시 열 수 있습니다.
  2. ‘기본 규격’에서 싱글을 선택하면 8504×6614 px, DPI 400×400이 입력됩니다. 필요한 경우 가로(px)·세로(px)·X DPI·Y DPI를 바꿉니다.
  3. ‘이미지 추가’로 파일 세 개를 선택하거나 이미지·폴더를 입력 목록에 놓습니다. 목록의 순서·원본명·전체 경로를 확인합니다.
  4. 필요하면 ‘위로’·‘아래로’로 순서를 바꿉니다. 첫 행이 001.tif, 두 번째가 002.tif가 됩니다.
  5. 쓰기 가능한 별도 출력 폴더를 선택합니다. 시작 번호 1, 자리수 3, 충돌 처리 ‘건너뛰기 (기본)’을 확인합니다.
  6. ‘변환 시작’을 누릅니다. 진행 단계와 최종 변환·건너뜀·실패 수를 확인합니다.
  7. 결과 폴더와 ‘결과 저장(JSON)’에서 처리 경로·상태·변환 파일의 규격을 확인합니다. 작업 기록이 필요하면 ‘로그 저장(TXT)’도 저장합니다.
참고

기존 001.tif가 있으면 기본 정책에서는 그대로 두고 첫 입력을 건너뜁니다. 기존 파일을 이번 작업의 결과로 바꾸려면 내용을 확인하고 덮어쓰기 정책을 명시적으로 선택하세요.

목차와 처음으로 ↑

3. 기본 규격·출력 픽셀 크기·DPI

기본 규격픽셀 해상도가로×세로 DPI출력 장수
싱글8504×6614 px400×400입력 파일 하나당 TIFF 한 장
멀티8504×13228 px400×800입력 파일 하나당 TIFF 한 장

싱글·멀티는 시작값을 빠르게 채우는 기본 규격입니다. 선택을 바꾸거나 ‘기본값 적용’을 누르면 아래 네 입력값을 해당 기본값으로 다시 채웁니다. 그다음 가로(px)·세로(px)·X DPI·Y DPI를 각각 수정할 수 있습니다. 사용자 설정도 입력 한 장당 단일 프레임 TIFF 한 장으로 저장됩니다.

확인 사항

원본 크기나 가로세로 비율이 목표와 달라도 목표 사각형 전체에 맞추어 늘이거나 줄입니다. 비율 유지, 여백 추가, 자르기 옵션은 제공하지 않습니다. 원본의 형상과 출력 픽셀 비율을 변환 전에 확인하세요.

DPI는 픽셀 해상도와 별도의 규격입니다. 멀티는 세로 픽셀 수와 세로 DPI가 모두 싱글의 두 배입니다. 세로 픽셀 수만 보고 물리적 높이도 두 배라고 해석하지 마세요.

입력동작입력 조건
가로(px)·세로(px)출력 픽셀 수를 바꾸며 목표 사각형 전체로 리사이즈각각 1 이상의 정수. 실제 메모리·저장 공간 안에서 선택
X DPI·Y DPI픽셀 크기와 별도로 TIFF에 저장되는 해상도 정보0보다 큰 유한한 숫자. 소수 허용, Windows 표현 범위 밖 값 거부
기본값 적용현재 선택한 싱글·멀티의 네 기본값 복원직접 입력한 값을 대체하므로 적용 뒤 확인

DPI만 바꾸면 출력 픽셀 수를 바꾸지 않습니다. 예를 들어 가로 1000 px는 X DPI 250에서 101.6 mm, X DPI 500에서 50.8 mm에 해당합니다. 물리 길이는 픽셀 수 ÷ DPI × 25.4 mm로 읽습니다. DPI를 바꾼 뒤 장비가 기대하는 실제 크기도 확인하세요.

4. 파일 선택·폴더 추가·드래그 앤 드롭

입력 방법추가되는 순서와 범위유의사항
이미지 추가파일 선택창에서 받은 파일 목록 순서최종 입력 표의 실제 순서를 확인
폴더 추가폴더 바로 아래 지원 이미지의 숫자 자연 정렬하위 폴더를 재귀 검색하지 않음
이미지·폴더 드롭넘겨받은 경로 순서. 폴더 내부는 자연 정렬목록 또는 안내 영역에 놓기
같은 경로 재추가목록에 이미 있으면 중복 추가하지 않음원본을 여러 번호로 복제하려면 번호 복제 기능 사용

지원 확장자는 .png, .jpg, .jpeg, .bmp, .tif, .tiff이며 대소문자를 구분하지 않습니다. 원본 M2 선택 목록의 .tiff 외에 .tif도 받을 수 있습니다. ZIP 압축파일은 직접 받지 않으므로 먼저 폴더에 풀고 추가합니다. 지원하지 않는 경로는 경고하고, 함께 받은 유효한 이미지는 목록에 추가합니다.

확인 사항

여러 프레임이 들어 있는 TIFF 등은 GDI+가 처음 연 첫 프레임만 변환합니다. 모든 페이지를 각각 내보내거나 합치는 작업은 하지 않습니다.

확장자는 입력 접수 기준이며 실제 이미지 읽기는 Windows GDI+가 수행합니다. 손상 파일이나 GDI+가 읽을 수 없는 데이터는 변환 중 오류가 될 수 있습니다. 원본 입력을 처리 도중 수정·삭제·교체하지 마세요.

목차와 처음으로 ↑

5. 입력 목록의 순서·선택·제거

  1. 목록의 ‘순서’ 열을 출력 번호의 상대 순서로 읽습니다. ‘원본명’이 같아도 ‘경로’가 다르면 서로 다른 입력일 수 있습니다.
  2. 행을 선택한 뒤 ‘위로’ 또는 ‘아래로’를 눌러 한 칸 이동합니다. 여러 행을 선택한 경우 선택된 행들의 상대 순서를 유지합니다.
  3. 필요 없는 항목은 ‘선택 제거’ 또는 목록에 초점이 있을 때 Delete로 제거합니다. ‘비우기’는 목록 전체를 지웁니다.
  4. 번호·경로·모드를 확인한 뒤 변환을 시작합니다. 작업이 시작되면 목록 추가·이동·제거·드롭은 잠깁니다.
폴더 파일: slice1.png, slice10.png, slice2.png
폴더 추가 후: slice1.png → slice2.png → slice10.png
시작 1 / 자리수 3: 001.tif → 002.tif → 003.tif
참고

파일 선택창이나 탐색기에서 보던 정렬을 그대로 신뢰하지 말고 변환 전 표의 순서를 확인하세요. 출력 번호는 원본 파일명에 있던 1·2·10을 해석해 결정하지 않습니다.

목차와 처음으로 ↑

6. 출력 폴더·시작 번호·자리수

설정규칙예시
출력 폴더공란 불가. 쓰기 가능한 폴더 지정입력 폴더와 구분된 새 결과 폴더 권장
시작 번호1 이상의 정수. 처리 대상마다 1씩 증가100 → 100.tif, 101.tif, 102.tif
자리수0~12의 정수. 번호 앞을 0으로 채울 최소 길이3 / 시작 1 → 001.tif
자리수 0앞자리 0을 채우지 않음시작 1 → 1.tif, 2.tif
출력 확장자항상 소문자 .tif원본이 PNG·JPEG·TIFF여도 동일

자리수는 번호를 자르는 규칙이 아닙니다. 자리수 3에서 1000번이 되면 1000.tif로 저장합니다. 기존 파일을 건너뛰어도 그 입력에 배정된 번호는 소비되며 이후 번호를 앞으로 당겨 채우지 않습니다.

목록 A.png, B.png, C.png / 시작 1 / 자리수 3
001.tif 존재 + 건너뛰기 → A는 건너뜀, B→002.tif, C→003.tif
참고

이름 충돌은 목표 경로의 존재 여부로 판단합니다. 기존 TIFF의 내용이 해당 입력과 같은지 비교한 뒤 건너뛰는 방식은 아닙니다.

7. 원본 GDI+ 변환과 4비트 팔레트 해석

  1. Windows GDI+로 입력 이미지를 읽습니다. 다중 프레임 입력은 첫 프레임을 사용합니다.
  2. 모드의 목표 크기를 가진 중간 이미지에 GDI+ DrawImage로 원본 전체를 그립니다. 목표 DPI를 설정합니다.
  3. GDI+의 원본 Clone 변환 경로로 4비트 인덱스 팔레트 이미지를 만듭니다.
  4. 16개 팔레트 항목의 RGB 색상을 반전합니다.
  5. 목표 DPI를 적용해 LZW 압축 TIFF로 저장하고 형식 태그를 검사합니다.

실제 결과는 4비트 VGA 16색 계열 팔레트의 인덱스 이미지입니다. 팔레트에 있는 색의 RGB를 반전하며, 검정~흰색의 균등한 회색 16단계 양자화로 대체하지 않습니다. 컬러 입력은 색과 인덱스의 관계가 변할 수 있고, 원본의 투명도도 그대로 보존하는 형식이 아닙니다.

참고

다른 이미지 라이브러리의 단순 4비트 변환·그레이스케일 변환·보간 설정으로 조용히 대체하지 않습니다. Windows GDI+에서 원본과 같은 변환 경로를 사용할 수 없으면 작업을 실패로 보고합니다.

원본 프로그램의 기준 출력과 비교하여 이 처리 순서를 검증했습니다. 원본 픽셀을 보존하는 PNG/TIFF 복사 작업과 결과가 다르므로, 원본 대 출력의 일치성 검사에서 픽셀 차이가 나타나는 것은 변환 의도에 포함될 수 있습니다.

목차와 처음으로 ↑

8. 건너뛰기·덮어쓰기와 원본 보호

정책기존 001.tif가 있을 때결과 해석
건너뛰기 (기본)기존 파일을 보존하고 해당 입력을 건너뜀기존 파일의 형식·내용은 새로 검사하지 않음
덮어쓰기새 변환·태그 검사가 성공한 파일로 교체원본 입력과 목표가 겹치면 작업 준비 단계에서 거부
처리 중 충돌 발생건너뛰기 정책이면 새 기존 파일을 보존변환한 임시 파일은 제거하고 건너뜀으로 기록

덮어쓰기는 모든 입력 경로와 모든 목표 경로의 겹침을 시작 전에 검사합니다. 첫 번째 결과가 뒤에서 읽을 다른 원본을 덮는 경우도 거부합니다. 같은 파일을 가리키는 경로 별칭도 검사하며, 게시 직전에 원본과의 겹침을 다시 확인합니다. 출력 폴더를 별도로 지정하면 이러한 충돌을 줄일 수 있습니다.

확인 사항

덮어쓴 기존 결과의 자동 백업은 만들지 않습니다. 필요한 이전 결과는 별도 폴더나 다른 이름으로 보관한 후 작업하세요. 중지·오류가 나도 앞서 완료하여 교체한 파일들을 자동으로 이전 상태로 되돌리지 않습니다.

각 파일은 출력 폴더 안의 임시 TIFF로 먼저 저장합니다. 정상 저장과 규격 검사가 끝난 파일만 최종 이름으로 게시합니다. 현재 파일이 실패하거나 중지되면 미완성 임시 파일을 제거하며, 그 현재 파일의 기존 목표는 유지됩니다.

10. 진행 단계·완료·실패 결과 읽기

상태의미후속 확인
이미지 읽기 / 해상도 변환 / 팔레트 / 저장 / 검사현재 입력의 네이티브 처리 단계큰 파일에서는 한 단계가 오래 걸릴 수 있음
변환 완료모든 입력이 변환 또는 건너뜀으로 처리됨변환 수와 건너뜀 수를 따로 확인
실패 · 부분 결과첫 실패에서 일괄 작업 중단실패 파일·오류 확인. 뒤의 입력은 아직 처리되지 않음
중지 · 부분 결과중지 요청 처리 후 미완성 현재 파일 정리이미 완료한 파일만 남음. 전체 완료 아님

진행률은 파일 인덱스 기준의 진행 안내이며 남은 시간 예측이 아닙니다. 최종 상태와 변환·건너뜀·실패 수로 작업 완료 여부를 판단하세요. 첫 실패 이후의 입력은 실패로 일괄 가산하지 않습니다. 예를 들어 전체 10개에서 변환 2, 실패 1이면 뒤의 7개는 미처리일 수 있습니다.

새로 파일을 추가·제거·재정렬하거나 기본 규격·픽셀 크기·DPI·출력·번호·정책을 변경하면 이전 보고서와 저장 버튼을 무효화합니다. 변경된 조건은 다시 변환해야 해당 조건의 보고서를 저장할 수 있습니다. 이미 완성한 출력 파일은 설정 변경으로 삭제하지 않습니다.

11. 중지·탭 이동·프로그램 종료

  • 변환은 별도 작업 스레드에서 입력 목록 순서대로 수행합니다. 다른 탭으로 이동해도 시작한 변환은 계속됩니다.
  • 변환 중 이 탭의 ‘중지’ 또는 이 탭을 선택한 상태에서 상단 ‘현재 작업 중단’을 누르면 중지를 요청합니다.
  • GDI+의 한 네이티브 호출을 중간에서 강제로 끊지 않습니다. 읽기·리사이즈·팔레트·저장 중인 단계가 끝날 때까지 중지 처리가 지연될 수 있습니다.
  • 중지 후 현재 파일의 미완성 임시 결과는 제거하고, 앞서 완료해 게시한 파일은 유지합니다. 건너뛴 기존 파일도 유지합니다.
  • 프로그램을 닫을 때 작업 중이면 중지와 임시 파일 정리가 끝나기를 기다린 뒤 종료합니다. 정리 완료 전 반복 실행이나 출력 폴더 이동을 피하세요.
참고

전체 작업에 대한 자동 롤백이나 자동 이어하기는 제공하지 않습니다. 재시작할 때 같은 입력 순서·모드·시작 번호·자리수를 사용하고 기존 파일 처리 정책을 확인하세요. 이미 있는 결과를 건너뛰면 해당 내용이 새 조건과 같은지는 다시 검사하지 않습니다.

12. JSON 결과와 TXT 로그 저장

  1. 완료·중지·실패 후 최종 상태를 확인합니다. 정상 보고서가 만들어졌다면 ‘결과 저장(JSON)’을 사용할 수 있습니다.
  2. ‘결과 저장(JSON)’을 눌러 전체 항목과 metadata가 포함된 보고서를 저장합니다.
  3. 화면의 작업 메시지가 필요하면 ‘로그 저장(TXT)’를 누릅니다. 입력 조건과 처리 상태·오류를 텍스트로 보관합니다.
  4. 저장 후 입력 조건을 바꾸면 보고서가 무효화되므로 필요한 기록은 조건 변경 전에 저장합니다.
보고서 항목의미
completed / cancelled전체 완료 여부 / 사용자 중지 여부
total / converted / skipped / failed전체 입력 / 새 변환 / 기존 파일 건너뜀 / 실제 실패 수
mode / output_dir / elapsed_seconds처리 모드 / 출력 폴더 / 소요 시간
items처리 순번, 원본·목표 경로, converted·skipped·failed 상태, 메시지
metadataconverted 항목의 실제 TIFF 형식·치수·비트·압축·DPI 등 검사값
error첫 실패의 오류 이유. 실패가 없으면 비어 있음
참고

화면 및 TXT 로그의 파일별 결과는 앞 2,000개까지 표시합니다. 전체 항목은 JSON에서 확인하세요. 변환 준비 단계에서 오류가 발생해 보고서가 없으면 JSON 저장은 사용할 수 없고, 작업을 시작한 뒤 발생한 오류는 화면 로그로 확인할 수 있습니다.

증상원인 또는 확인점해결 방법
변환 시작 버튼 비활성입력 없음, 출력 공란, 잘못된 픽셀·DPI·번호·자리수픽셀은 양의 정수, DPI는 유한한 양수, 시작≥1, 자리수 0~12 확인
ZIP을 놓았는데 추가되지 않음압축파일 직접 변환 미지원먼저 압축을 푼 폴더 추가
폴더의 일부 파일이 없음하위 폴더·미지원 확장자·이미 추가된 동일 경로해당 하위 폴더를 별도 추가하고 지원 목록 확인

메모리·저장·형식 오류대형 이미지 처리, 파일 잠금, 여유 공간, 손상·미지원 데이터오류 파일 확인 후 메모리·공간 확보, 다른 출력 위치나 정상 입력으로 재시도

출력 높이·모양이 예상과 다름사용자 픽셀·DPI와 목표 사각형 전체 리사이즈네 출력값·입력 비율 확인. 기본 규격을 다시 선택하면 사용자 설정이 초기화됨

싱글은 약 5,625만 픽셀, 멀티는 약 1억 1,249만 픽셀입니다. 4비트 결과 파일이 작더라도 변환 과정에서는 32비트 중간 이미지와 팔레트 이미지 등을 만들므로 수백 MB 이상의 메모리가 필요할 수 있습니다. 입력 파일 크기와 운영체제 상태에 따라 더 늘 수 있습니다. 한 번에 여러 변환 작업을 병렬 실행하지 않고 순차 처리합니다.

동작에는 Windows의 GDI+가 필요합니다. 임의의 외부 이미지 변환 프로그램을 호출하거나 .NET 런타임을 따로 설치하는 방식은 사용하지 않습니다. 큰 이미지의 처리 시간은 CPU·메모리·저장장치·입력 특성에 따라 달라지며 특정 완료 시간을 보장하지 않습니다.

참고

형식 검사를 통과한 TIFF라도 투입할 장비·뷰어가 기대하는 픽셀 규격과 팔레트 의미를 확인하세요. 문제가 발생하면 원본을 보존하고 JSON의 해당 항목·오류와 TXT 로그를 함께 확인하면 입력 문제와 저장 문제를 구분하기 쉽습니다.

15. 입력값 자동 저장과 복원

통합 프로그램을 정상 종료하면 입력값을 사용자별로 저장합니다. 다음 실행에서 이 도구를 열 때 저장한 값을 복원하며, 열지 않은 탭의 이전 설정도 유지합니다. 계산이나 파일 처리를 자동으로 시작하지 않습니다.

  • 저장 대상: 입력 숫자·문자·선택·체크 상태·원본 경로·입력 목록과 작업에 필요한 배치·프로파일. 이미지 변환의 사용자 픽셀·DPI와 오븐의 언어·불러온 열전대 수치도 포함합니다.
  • 계산 결과·로그·진행 중 작업·이미지와 메쉬 원본은 설정에 저장하지 않습니다. 결과는 필요한 CSV·JSON·HTML·STL 등으로 따로 저장합니다.
  • 저장 위치: Windows는 %LOCALAPPDATA%\BJT_Tools\settings.json. Linux는 $XDG_CONFIG_HOME/BJT_Tools/settings.json 또는 ~/.config/BJT_Tools/settings.json입니다.
  • 원본이나 변환 캐시를 이동·삭제하면 복원한 경로를 사용할 수 없을 수 있습니다. 복원된 입력과 실제 파일을 확인한 뒤 실행합니다.
  • 강제 종료·프로세스 종료·전원 차단 직전의 변경은 정상 종료 저장에 포함되지 않을 수 있습니다. 저장 실패 시 경고·오류 기록을 확인하고 기존 설정을 보존합니다.
참고

손상된 설정은 기본값으로 시작하며, 다음 저장 시 손상 파일을 settings.json.corrupt-시각 이름으로 보관합니다. 복원할 수 없는 숫자형 항목은 기본값을 사용할 수 있으므로 실행 전 입력을 확인하세요.
