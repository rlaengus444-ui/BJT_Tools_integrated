1. 제품 개요와 적용 작업

이 도구는 2개 이상의 슬라이싱 이미지 폴더를 입력받아 대응하는 이미지 묶음마다 한 장의 합성 이미지를 저장합니다. 이미 같은 좌표에 놓인 여러 형상을 합치거나, 밝기 최대·최소값을 취하거나, 임계값으로 재료 영역을 합집합 처리할 때 사용합니다. 위치 이동·회전·자동 정렬 기능은 이 탭에서 제공하지 않으므로 위치를 바꿀 때에는 배치·합성 탭에서 먼저 준비합니다.

  1. 입력 폴더를 2개 이상 등록합니다.
  2. 레이어를 연결할 매칭 방식과 합성에 사용할 겹침 방식을 선택합니다.
  3. 이미지 크기가 다를 때 처리할 정책과 출력 파일명을 정합니다.
  4. 출력 폴더·덮어쓰기 설정을 확인하고 겹치기를 시작합니다.
  5. 로그의 처리 묶음 수·첫 출력 크기·최종 요약과 실제 출력 파일을 확인합니다.
참고

입력 파일은 읽기만 하며 결과는 출력 폴더에 저장합니다. 출력 폴더를 입력 폴더와 겹치게 지정하면 같은 이름의 입력이 덮어써질 수 있으므로 작업별 독립 출력 폴더를 지정하십시오.

2. 빠른 시작

  1. [폴더 추가]를 눌러 첫 번째 폴더를 선택하고 반복하여 나머지 폴더를 추가합니다. 목록 영역에 여러 폴더를 동시에 드래그앤드롭할 수도 있습니다.
  2. 첫 폴더를 등록하면 출력 폴더가 비어 있을 때 첫 폴더 이름에 _N_overlay를 붙인 경로가 자동 입력됩니다. 원하는 경로인지 확인하거나 [찾기]로 바꿉니다.
  3. 같은 숫자 파일명으로 층이 정리되어 있다면 매칭 방식=파일명 기준, 크기 처리=오류로 시작하여 데이터 일치 여부를 확인합니다.
  4. 흰 재료·검정 배경 이미지는 겹침 방식=grayscale max로 밝기를 유지하거나 binary union으로 이진화합니다.
  5. [겹치기 시작]을 누릅니다. 진행률과 ETA, 첫 출력 파일명과 크기를 로그에서 확인합니다.
  6. 완료 알림을 확인한 뒤 탐색기에서 지정 출력 폴더를 열어 첫 층·중간 층·마지막 층을 확인합니다. 이 탭은 이미지 미리보기나 완료 후 폴더 자동 열기를 제공하지 않습니다.

목록의 [선택 삭제]는 선택한 입력 경로를 제거하고 [전체 삭제]는 목록을 비웁니다. 폴더 자체나 파일을 삭제하지 않습니다. 목록을 지워도 이미 입력한 출력 경로는 유지되므로 다른 작업을 시작할 때 다시 확인합니다.

3. 입력 형식과 레이어 매칭

항목규칙
입력 수최소 2개 폴더. 같은 경로의 중복 등록은 생략합니다.
지원 이미지PNG, BMP, TIF, TIFF, JPG, JPEG. 폴더 바로 아래 파일만 수집하며 하위 폴더는 탐색하지 않습니다.
읽기 모드모든 입력을 8비트 그레이스케일로 변환하여 계산합니다. RGB 색상은 보존되지 않습니다.
자연 정렬문자열 속 숫자를 숫자로 비교합니다. 예: layer1.png → layer2.png → layer10.png.
정렬 순서 기준각 폴더를 자연 정렬한 뒤 같은 순번끼리 묶습니다. 처리 수는 가장 이미지가 적은 폴더의 개수입니다.
파일명 기준모든 폴더에 공통으로 존재하는 정확히 같은 전체 파일명만 묶습니다. 확장자와 대소문자도 매칭 키에 포함됩니다.
목록 드롭폴더는 그대로 등록합니다. 이미지 파일을 드롭하면 그 파일의 부모 폴더를 등록합니다.
출력 경로 드롭첫 경로를 사용하며 파일을 드롭하면 그 부모 폴더를 출력 경로로 지정합니다.
확인 사항

정렬 순서 기준에서 A에 1,2,3이 있고 B에 1,3이 있으면 두 번째 묶음은 A의 2와 B의 3입니다. 자동으로 누락 층을 찾거나 보충하지 않습니다. 같은 층 번호를 연결해야 한다면 파일명 기준을 사용하고 누락 파일을 먼저 확인하십시오.

파일명 기준도 공통으로 존재하지 않는 파일을 오류로 처리하지 않고 제외합니다. 예를 들어 A={1.png,2.png,3.png}, B={1.png,3.png,4.png}이면 1.png와 3.png만 처리합니다. 공통 이름이 하나도 없으면 실행이 실패합니다.

threshold, background, material 입력은 숫자여야 합니다. 소수는 정수 변환 후 처리하지만 의도한 결과를 명확히 하려면 0~255의 정수를 입력합니다. threshold와 재료 방향은 binary union 계산 및 최종 통계에 쓰이며 grayscale max/min과 add clamp의 밝기 계산식을 바꾸지 않습니다. background는 크기 패딩에도 쓰입니다.

참고

이 탭에는 mm 크기·DPI·층두께 설정이 없습니다. 픽셀 좌표로 계산하며 출력 저장 시 별도 DPI를 지정하지 않습니다. 원본의 물리 해상도 메타데이터 보존을 전제로 사용하지 마십시오.

5. 겹침 방식 선택과 숫자 예시

다음은 같은 좌표의 입력 픽셀이 A=80, B=200일 때의 결과입니다. threshold=128, background=0, material=255, 밝은색/흰색 선택을 가정합니다.

방식연산결과·용도
grayscale maxmax(80,200)200. 밝은 영역을 합치면서 중간 밝기를 유지합니다.
grayscale minmin(80,200)80. 가장 어두운 값을 유지합니다. 검정 재료·흰 배경 합성에 활용할 수 있습니다.
binary union80<128, 200≥128 → 하나라도 재료255. 재료가 한 입력에만 있어도 출력 재료이며 중간 밝기는 남지 않습니다.
add clamp80+200=280 → 최대 255255. 모든 입력 밝기를 더하고 255에서 제한합니다.

추가 예로 A=40, B=60이면 max=60, min=40, 밝은 재료 union=0, add=100입니다. A=128은 밝은 재료 조건 ≥128에 포함되며 어두운 재료 조건 ≤128에도 포함됩니다. 임계값과 정확히 같은 픽셀이 어느 쪽에 포함되는지 확인하십시오.

확인 사항

binary union에서 어두운 재료를 사용할 때는 보통 밝은색/흰색을 해제하고 background=255, material=0으로 함께 바꿉니다. 체크만 해제하고 출력 밝기를 그대로 두면 판정과 표시 색상이 서로 반대가 될 수 있습니다.

6. 크기 처리와 캔버스 기준

옵션처리예: A=1000×800, B=800×1000 px
오류묶음 안 이미지 크기가 하나라도 다르면 중단합니다.크기 불일치 오류. 해당 묶음은 저장되지 않습니다.
작은 이미지 패딩가로 최댓값 × 세로 최댓값의 캔버스에 좌상단 기준으로 배치하고 부족한 영역을 background 값으로 채웁니다.1000×1000 px. A 아래와 B 오른쪽에 패딩.
큰 이미지 크롭가로 최솟값 × 세로 최솟값의 좌상단 공통 영역만 남깁니다.800×800 px. A 오른쪽과 B 아래 부분 제거.

패딩과 크롭은 이미지 확대·축소가 아닙니다. 좌상단 (0,0)을 맞출 뿐 중심이나 형상의 위치를 자동으로 맞추지 않습니다. 각 레이어 묶음에서 크기를 다시 계산하므로 입력 크기가 층마다 달라지면 출력 크기도 층별로 달라질 수 있습니다.

확인 사항

패딩값은 합성에 참여합니다. grayscale max의 검정 배경에는 0이 자연스럽고 grayscale min의 흰 배경에는 255가 자연스럽습니다. max 패딩에 255를 쓰면 패딩 부분이 흰색으로 결과에 나타납니다. 크롭은 실제 픽셀을 제거하므로 필요한 형상이 공통 영역 밖에 없는지 확인합니다.

7. 작업 예제 ① 세 폴더의 흰색 재료 합성

예제 조건: Body, Support, Marker 폴더에 각각 1.png~80.png가 있으며 모두 2000 × 2000 px, 검정 배경·흰 재료라고 가정합니다. 세 형상이 이미 같은 픽셀 좌표계에 있습니다.

  1. Body, Support, Marker 순서로 [폴더 추가]를 반복하여 세 폴더를 등록합니다.
  2. 출력 폴더를 새 경로 Combined_80으로 지정합니다.
  3. 매칭 방식=파일명 기준, 겹침 방식=binary union, 크기 처리=오류를 선택합니다.
  4. threshold=128, 프린팅 영역이 밝은색/흰색=선택, background=0, material=255를 입력합니다.
  5. 출력 파일명=첫 번째 폴더 파일명, 덮어쓰기=해제로 설정하고 [겹치기 시작]을 누릅니다.
  6. 로그의 처리 묶음 수가 80인지, 첫 출력이 1.png이며 2000×2000인지 확인합니다. 완료 후 80.png까지 생성되었는지 확인합니다.
Body/1.png     + Support/1.png     + Marker/1.png     → Combined_80/1.png
Body/2.png     + Support/2.png     + Marker/2.png     → Combined_80/2.png
…
Body/80.png    + Support/80.png    + Marker/80.png    → Combined_80/80.png

한 좌표에서 세 입력이 0,255,0이면 출력은 255입니다. 0,127,0이면 출력은 0입니다. 경계의 127 같은 중간 밝기도 유지하려면 binary union 대신 grayscale max를 선택합니다. 이때 같은 좌표 출력은 127이 됩니다.

8. 작업 예제 ② 검정 재료와 다른 크기 처리

예제 조건: Dark_A의 1.bmp~60.bmp는 1200×800 px, Dark_B는 1000×800 px입니다. 두 폴더 모두 흰 배경·검정 재료이며 좌상단이 같은 기준점입니다. 작은 이미지에 없는 오른쪽 영역은 흰 배경으로 취급하고 결과는 1200×800 px로 만듭니다.

  1. Dark_A와 Dark_B를 추가하고 새 출력 폴더 Dark_union을 지정합니다.
  2. 매칭 방식=파일명 기준, 겹침 방식=binary union, 크기 처리=작은 이미지 패딩을 선택합니다.
  3. 프린팅 영역이 밝은색/흰색을 해제하고 threshold=128, background=255, material=0을 입력합니다.
  4. 출력 파일명=순번 파일명을 선택합니다. 첫 폴더 확장자가 BMP이므로 결과 이름은 1.bmp~60.bmp입니다.
  5. 실행 후 첫 출력 크기가 1200×800인지 확인합니다. B의 오른쪽 200 px는 255로 채워져 검정 재료를 추가하지 않습니다.

같은 좌표에 A=240, B=70이면 B가 ≤128 조건을 만족하므로 결과는 0입니다. A=240, B=200이면 둘 다 재료가 아니므로 255입니다. 중간 회색을 유지하려면 grayscale min을 사용할 수 있으며 앞의 두 결과는 각각 70과 200이 됩니다.

참고

순번 파일명은 실제 처리 순서를 1부터 다시 붙이는 기능입니다. 원래 공통 이름이 61.bmp~120.bmp라면 순번 출력은 1.bmp~60.bmp가 되며 원래 층 번호가 유지되지 않습니다.

9. 출력·로그·중단 동작

출력은 8비트 그레이스케일(L)이며 첫 번째 폴더의 대응 파일명 또는 확장자를 사용합니다. PNG로 입력하면 PNG로, JPEG로 입력하면 JPEG로 저장합니다. JPEG는 손실 형식이므로 계산된 픽셀을 그대로 보관하려는 슬라이싱 작업에서는 입력·출력 형식을 확인해야 합니다. 출력 확장자를 따로 지정하는 UI는 없습니다.

진행률은 처리 완료한 묶음 수를 기준으로 표시하고 ETA는 지금까지의 평균 시간으로 추정합니다. 최종 요약의 입력 material pixel 합산은 여러 입력에서 판정한 재료 픽셀의 총합이며, 출력 material pixel은 저장 전 합성 배열에서 같은 임계값 규칙으로 센 값입니다. 출력/입력 비율은 참고 통계이며 mm 면적이나 출력 품질 점수가 아닙니다.

  1. [작업 중단] 또는 통합 프로그램 상단 [현재 작업 중단]을 누르면 중단을 요청합니다.
  2. 중단 상태는 다음 이미지 묶음을 시작하기 전에 확인합니다. 이미 처리 중인 묶음의 읽기·계산·저장이 끝날 수 있습니다.
  3. 저장된 결과 파일은 남습니다. 오류나 중단 시 자동 삭제·자동 복구·재개 기능은 없습니다.
  4. 다시 [겹치기 시작]을 누르면 목록 전체를 처음부터 처리합니다. 빈 출력 폴더로 바꾸거나 덮어쓰기 정책을 확인하고 재실행합니다.
확인 사항

덮어쓰기 해제는 실행 전체를 미리 검사하는 기능이 아닙니다. 일부 결과가 저장된 뒤 기존 파일을 만나면 그 지점에서 실패하고 앞서 저장한 파일은 남습니다. 또한 출력 폴더의 오래된 파일은 자동 정리하지 않습니다.

10. 문제 해결과 용어

증상·메시지확인 및 조치
입력 폴더를 최소 2개 이상 추가서로 다른 입력 폴더 두 개 이상을 등록합니다.
이미지가 없는 폴더지원 확장자의 이미지가 선택 폴더 바로 아래에 있는지 확인합니다.
공통으로 존재하는 파일명이 없음확장자·대소문자를 포함한 파일명을 대조합니다. 실제 층 순서가 맞는 경우에만 정렬 순서 기준을 사용합니다.
결과 장수가 예상보다 적음정렬 순서는 최소 개수만, 파일명 기준은 공통 이름만 처리합니다. 로그의 폴더별 수와 처리 묶음 수를 비교합니다.
이미지 크기가 서로 다름입력 규격을 맞추거나 패딩·크롭을 선택합니다. 중심 정렬이 필요한 경우 배치 탭에서 준비합니다.
출력 파일이 이미 존재새 출력 폴더를 사용하거나 의도한 경우 덮어쓰기를 선택합니다. 이미 저장된 파일은 유지됩니다.
결과가 모두 흰색·검정색겹침 방식, 재료 방향, threshold, background, material 값을 함께 점검합니다.
숫자 입력 오류threshold·background·material에 숫자를 입력합니다. 일반적으로 0~255 정수를 사용합니다.
  • 묶음: 같은 레이어로 대응시킨 각 입력 폴더의 이미지 집합입니다.
  • threshold(임계값): 밝기를 재료와 비재료로 나누는 기준값입니다.
  • union(합집합): 하나 이상의 입력에서 재료인 픽셀을 출력 재료로 만드는 연산입니다.
  • 패딩: 작은 이미지 주변의 부족한 캔버스를 지정 밝기로 채우는 처리입니다.
  • 크롭: 정해진 공통 영역 밖의 픽셀을 잘라내는 처리입니다.
  • clamp(제한): 계산한 밝기를 0~255 범위에 맞추는 처리입니다.

11. 입력값 자동 저장과 복원

통합 프로그램을 정상 종료하면 입력값을 사용자별로 저장합니다. 다음 실행에서 이 도구를 열 때 저장한 값을 복원하며, 열지 않은 탭의 이전 설정도 유지합니다. 계산이나 파일 처리를 자동으로 시작하지 않습니다.

  • 저장 대상: 입력 숫자·문자·선택·체크 상태·원본 경로·입력 목록과 작업에 필요한 배치·프로파일. 이미지 변환의 사용자 픽셀·DPI와 오븐의 언어·불러온 열전대 수치도 포함합니다.
  • 계산 결과·로그·진행 중 작업·이미지와 메쉬 원본은 설정에 저장하지 않습니다. 결과는 필요한 CSV·JSON·HTML·STL 등으로 따로 저장합니다.
  • 저장 위치: Windows는 %LOCALAPPDATA%\BJT_Tools\settings.json. Linux는 $XDG_CONFIG_HOME/BJT_Tools/settings.json 또는 ~/.config/BJT_Tools/settings.json입니다.
  • 원본이나 변환 캐시를 이동·삭제하면 복원한 경로를 사용할 수 없을 수 있습니다. 복원된 입력과 실제 파일을 확인한 뒤 실행합니다.
  • 강제 종료·프로세스 종료·전원 차단 직전의 변경은 정상 종료 저장에 포함되지 않을 수 있습니다. 저장 실패 시 경고·오류 기록을 확인하고 기존 설정을 보존합니다.
참고

손상된 설정은 기본값으로 시작하며, 다음 저장 시 손상 파일을 settings.json.corrupt-시각 이름으로 보관합니다. 복원할 수 없는 숫자형 항목은 기본값을 사용할 수 있으므로 실행 전 입력을 확인하세요.
